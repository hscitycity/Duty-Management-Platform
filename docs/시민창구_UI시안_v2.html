두 앱에서 실제로 가져온 것

티맵
제보 버튼이 지도 위에 떠 있다

주행 중 한 손으로 눌러야 하므로 메뉴 진입 단계가 없습니다. 우리 창구도 지도 화면에서 바로 신고가 시작되게 하고, 버튼은 엄지가 닿는 좌하단에 둡니다.

티맵
유형 다섯 개, 색으로 구분

사고·통제·공사·위험/장애물·단속카메라 다섯 개를 한 단계에 놓고 원형 컬러 아이콘을 씁니다. 색이 글자보다 먼저 읽힙니다. 우리는 야간 다발 5종을 1단계로 올리고 나머지 분야는 “그 밖”으로 접었습니다. 지금의 8분야 2계층은 최소 두 번을 눌러야 합니다.

티맵
“근처 제보 보기”를 신고 버튼 옆에

제보 전에 남이 올린 것을 먼저 봅니다. 중복 제보가 줄고, 시민은 “이미 신고됐다”를 알고 안심합니다. 행정에서는 중복 민원 감소와 처리 투명성을 동시에 얻는 장치입니다.

티맵
“24분 전 · 2명 제보”

신선도와 중복 집계를 한 줄로 보여줍니다. 우리는 같은 유형·반경 100m·24시간 이내를 한 건으로 묶고, 신고자 수만큼 긴급도를 올립니다. “도움됐어요”는 사람 평가가 아니라 제보가 아직 유효한지 묻는 장치이므로, “아직 그대로인가요?” 형태로 가져옵니다. 미처리 건의 신선도를 시민이 갱신해 줍니다.

배민
진행 막대 위에 담당자를 올린다

접수·시작·완료 3단계 막대 위에 라이더 아이콘이 현재 위치만큼 이동합니다. 글로 “처리중”이라 쓰는 것보다 훨씬 직관적입니다. 우리는 접수·출동·현장확인·완료 4단계로 두고, 담당 순찰조 아이콘을 막대 위에 올립니다.

배민
도착 예정 시각을 함께

“오후 5:28 도착예정”처럼 남은 시간이 아니라 시각으로 표기합니다. 경로 계산에 소요시간이 이미 들어 있으므로 값을 꺼내 쓰기만 하면 됩니다.

배민
현황 카드는 위, 지도는 아래

상태 요약을 먼저 읽고 필요하면 지도를 봅니다. 담당자 위치와 목적지만 남기고 지도 정보는 줄입니다. “주문정보 열기”처럼 상세는 접어 둡니다.
