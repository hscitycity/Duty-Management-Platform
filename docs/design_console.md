## 1. 범위

당직자용 **실시간 상황판(#duty)** 한 화면의 구조 기준.

**적용 대상이 아닌 것**: 시민 신고창구(#cit)와 처리 현황(#track)은 밝은 톤의 모바일 흐름을 유지한다. 관제 콘솔 문법을 시민 화면에 옮기지 않는다. 대시보드(#dash)·신속기동단(#road)·조치지시(#cmd)는 이 문서의 토큰과 패널 규칙을 따르되 레이아웃은 각자의 목적을 우선한다.

## 2. 설계 철학

**[채택] 지도 위 점은 좌표가 아니라 민원 객체다.**
원본의 "온톨로지 객체" 개념을 우리 수준으로 낮춘 것. 지도에 올라가는 것은 좌표 배열이 아니라 **접수번호·유형·긴급도·처리구분·담당부서·처리이력을 가진 민원**이다. 이게 전제되어야 선택 → 속성 확인 → 조치 지시가 한 자리에서 이어진다. 이미 `complaints` 테이블이 17개 속성을 갖고 있으므로 조건은 충족돼 있다.

**[채택] 공간과 시간은 분리하지 않는다.**
타임라인을 접어도 시간 범위는 지도에 계속 적용된다. 당직 업무에서 "지금 열려 있는 민원"과 "오늘 처리한 민원"과 "이번 주 상습지점"은 같은 지도의 다른 시각일 뿐이다.

**[보류] 관계 탐색(Search Around).**
팔란티어의 일급 기능이지만 우리 데이터는 민원 단건 중심이라 타고 갈 관계가 얕다. 대신 **유사 민원 조회**를 그 자리에 넣는다 — 선택한 민원의 반경·유형·기간이 겹치는 건을 지도에 함께 띄우는 기능. 급증 탐지와 같은 판정을 사람이 직접 확인하는 수단이 된다.

**[채택] 정보 밀도가 여백보다 우선한다.**
단, 야간 근무자가 장시간 보는 화면이므로 최소 글자 크기는 원본보다 올린다(11px 이상). 문서 화면이 아니라 관제 화면이라는 점은 같지만, 4K 다중 모니터가 아니라 사무용 노트북·모니터가 기본 환경이다.

**[채택] 색은 인코딩이지 장식이 아니다.**
우리 화면에서 **색은 긴급도·처리상태 축 하나에만** 매핑한다. 부서·관할구를 색으로 나누지 않는다(라벨·아이콘으로 구분).

**[철회] 다크 배색.**
관제 콘솔이라고 어둡게 만들 이유는 없다. 야간 근무를 위한 야간모드는 이미 별도 토글로 있고, 기본 화면까지 어둡게 하면 문서 생성·목록 판독이 오히려 불리하다.

## 3. 화면 구조

```
┌──────────────────────────────────────────────────────────────────┐
│ 로고 │ 검색 │ 필터(전체·긴급·미처리) │ LIVE │ 시간범위 │ 시계·편성 │ 소속 │  명령 바 44px
├────────────┬─────────────────────────────────────┬───────────────┤
│  민원      │                                     │  선택 상세     │
│  레이어    │              지  도                  │  조치 실행     │
│  자원      │        (도구는 지도 위 오버레이)      │  AI 분석      │
│            │                                     │  처리 이력     │
├────────────┴─────────────────────────────────────┴───────────────┤
│  실시간 이벤트 │ 시간대별 접수 │ 처리 지표          (접기 가능)     │  하단 스트립
└──────────────────────────────────────────────────────────────────┘
```

**페이지 전체 스크롤은 없다.** 각 패널이 자기 영역 안에서만 스크롤한다. 이것이 현재 상황판(문서형 카드 나열)과의 가장 큰 차이다.

### 3.1 좌측 패널 3종 [채택]

원본의 Layers / Find / Histogram / Info 4종을 우리 업무에 맞춰 3종으로 줄였다.

| 탭 | 역할 | 원본 대응 |
|---|---|---|
| **민원** | 접수 목록. 긴급 우선·최신순. 행 클릭 시 지도 포커스 + 우측 상세 | Find |
| **레이어** | 데이터 레이어 20종 가시성·순서·스타일 | Layers |
| **자원** | 가용 인력·용역업체 현황, 출동 배정 대상 | (신규) |

**[채택] 민원 목록은 구획으로 나눈다.**
긴급이 일반 사이에 섞이면 놓친다. 구획 순서는 **긴급 → 일반 → 처리중**이고, 각 구획에 고정 머리글과 건수를 붙인다. 긴급 구획은 항상 최상단이며 접을 수 없다. 완료는 목록에서 빠져 대시보드로 이관한다.

**[채택] 두 분류 체계를 한 화면에 섞지 않는다.**

| 화면 | 사용자 | 분류 축 |
|---|---|---|
| 상황판 `#duty` | 일반 직원·당직자 | **긴급 / 일반** |
| 신속기동단 `#road` | 도로교통 기동단 | **즉시(4h) / 단기(7일) / 중장기(6개월)** |

처리구분은 상황판 목록에 노출하지 않는다. 도로교통 민원이 기동단으로 넘어간 뒤 그 화면에서만 쓴다. 보는 사람이 다르고 판단 기준이 다르기 때문이다.

**[보류] Histogram 패널.** 값 분포를 보며 필터하는 방식은 훌륭하지만, 우리 민원 속성은 범주형(유형·구분·상태)이 대부분이라 분포 차트의 이득이 작다. 대신 **명령 바의 필터 칩**과 **하단 스트립의 시간대별 막대**가 그 역할을 나눠 갖는다. 데이터가 쌓여 분포 분석이 의미를 갖는 시점에 재검토한다.

### 3.2 우측 패널 [채택]

| 구획 | 내용 |
|---|---|
| **헤더** | 접수번호 · 유형 · 위치 |
| **조치** | 인력 투입 · 문자 인계 · 현장 확인 · 종결 (4개 버튼) |
| **속성** | 접수시각·긴급도·처리구분·법적 소관·처리 주체·도로등급·좌표 |
| **AI 분석** | 유사 민원, 급증 판정, 배정 근거 |
| **처리 이력** | 시각이 붙은 타임라인 |
| **현장** | 신고 사진, 결과보고 사진 |

**조회와 지시가 같은 패널에 있다**는 원본 원칙을 그대로 가져왔다. 선택 → 확인 → 조치가 한 자리에서 끝난다.

### 3.3 지도 위 도구 [채택]

원본은 상단 툴바 7종(Select·Search Around·Draw·Capture·Measure·Annotate·Delete)이지만, 우리는 지도 위 오버레이로 배치한다.

| 위치 | 도구 |
|---|---|
| 좌상단 칩 | 주요 레이어 빠른 토글(민원·출동·기상특보·돌발·소방경찰) |
| 우상단 세로 버튼 | 전체화면 · 항공 · 기상 · 확대 · 축소 · 내 위치 |
| 좌하단 HUD | 긴급·처리중·평균 처리시간·출동 지표 |
| 우하단 | 축척 |

**[채택] Capture는 일급 도구로 둔다.** 원본이 화면 캡처를 앱 안에 넣은 이유가 우리에게 그대로 적용된다 — 당직 업무의 산출물이 보고서이기 때문이다. 다만 우리는 이미 **일일보고·민원접수서 hwpx 자동 생성**이 있으므로, 지도 캡처는 그 문서에 삽입할 이미지를 뽑는 용도로 붙인다.

**[보류] Draw·Measure·Annotate.** 정식 구축 단계 기능. 지금은 상습지점 표시·현장 반경 확인 수요가 확인되지 않았다.

### 3.4 패널 크기 [채택]

| 영역 | 값 |
|---|---|
| 명령 바 | 높이 44px 고정 |
| 좌측 패널 | 308px (1200px 이하에서 250px) |
| 지도 | 잔여 전체, 최소 폭 480px |
| 우측 패널 | 340px (1200px 이하에서 290px) |
| 하단 스트립 | 132px, 접기 가능 |

**[보류] 패널 폭 사용자 리사이즈·저장.** 우선순위 낮음. 다만 1280px 노트북에서 지도가 480px 이상 확보되는지는 반드시 확인한다. 현재 구현의 좌우 최소폭(430·440px)이 지도를 500px대로 누르는 문제가 이 값 때문이었다.

### 3.5 소속 선택 [채택]

접속자의 소속에 따라 보이는 범위가 정해진다. 나열식으로 길게 늘어놓지 않고 **3단계로 고른다.**

| 구분 | 대상 | 권한 |
|---|---|---|
| **상황실** | 시장 · 부시장 · 재난안전상황실 | 전체 범위 + 조치지시(`#cmd`) |
| **부서** | 본청·구청 부서 (선택 시 목록 표시) | 부서 소관 전건 |
| **행정복지센터** | 29개 읍면동 (선택 시 목록 표시) | 관내 전체 |

- 헤더에는 **선택 결과만 짧게** 표시한다(예: `팔탄면행정복지센터`). 전체 경로를 늘어놓지 않는다.
- 목록은 `행정조직도.md`를 근거로 구성한다.
- 선택값을 저장해 다음 접속 시 그 범위로 시작한다.

## 4. 레이어

### 4.1 조작 [채택]

- **표시/숨김** 토글 — 눈 아이콘
- **순서 변경** — 드래그. 목록에서 위에 있는 레이어가 위에 렌더된다. **z-order를 코드에 고정하지 말고 상태로 저장한다**
- **[보류] 이름 변경·객체 분리** — 우리 레이어는 시스템이 정의한 20종 고정이라 사용자가 새 레이어를 만들 일이 없다

### 4.2 우리 레이어 20종 분류 [채택]

| 그룹 | 레이어 |
|---|---|
| 상황 | 민원 핀 · 출동 경로 · 관할 경계 · 가용 인력 |
| 기상·환경 | 기상특보 · 강수 레이더(Windy) · 미세먼지 · 도로 기상 |
| 교통 | CCTV(ITS+UTIC) · 돌발상황 · 불법주정차 |
| 시설 | 지적(벡터타일) · 건축물대장 · 소방·경찰 · 심야약국 |
| 안전 | 범죄주의구간 · 어린이 안전시설 · 행사·인파 |
| 배경 | 일반 · 항공 · 야간 (택 1) |

### 4.3 시각화 유형 [채택]

원본 6종 중 우리가 쓰는 것:

| 유형 | 우리 용도 |
|---|---|
| **Points** | 민원 핀, 시설, CCTV |
| **Lines and polygons** | 출동 경로, 관할 경계, 지적 필지 |
| **Clusters** | 민원 누적 시 묶음 표시 (D-06) |
| **Choropleths** | 읍면동별 민원 밀도 — 대시보드에서 |
| **Tracks** | 출동 인력 이동 궤적 |
| **Timeline events** | 하단 스트립의 이벤트 행 |

### 4.4 심볼 인코딩 [채택]

| 채널 | 인코딩 |
|---|---|
| 모양 | 민원 유형 (도로·침수·동물·가로등 등) |
| 색 | **긴급도·처리상태만** (긴급 적색 / 처리중 주황 / 완료 청색 / 대기 회색) |
| 크기 | 중복 신고 건수 |
| 테두리 | 선택·포커스 |

- 점멸(펄스)은 **긴급 미배정** 상태에만 허용한다
- 클러스터 배지는 개수와 함께 **내부 최고 심각도 색**을 쓴다. 초록 뭉치 안에 긴급이 숨으면 안 된다
- 완료 민원은 상황판에서 제거하고 대시보드로 이관한다(기존 규칙 유지)

**레이어 토글 상태 표기**: 켜짐은 **진한 배경 + 강조색**, 꺼짐은 **흐린 배경 + 회색**이다. 반대로 만들면 무엇이 켜져 있는지 읽을 수 없다. `aria-pressed`도 함께 맞춘다.

## 5. 시간 모델

원본에서 가장 중요한 장. 우리도 세 개념을 분리해서 구현한다. **[검증]**

### 5.1 세 가지 시간 개념

| 개념 | 정체 | 우리 UI |
|---|---|---|
| **선택 시각** | 지도가 보여주는 "지금" 한 시점 | 하단 스트립 타임라인 커서 |
| **시간 범위** | 타임라인이 보여주는 창 | 명령 바의 1시간·6시간·24시간 |
| **필터 구간** | 강조할 구간 | 타임라인 드래그 |

### 5.2 실시간 모드 [채택]

- 명령 바의 **LIVE** 표시가 켜져 있으면 선택 시각이 현재를 자동 추종한다
- 갱신은 Supabase 실시간 구독 + 20초 폴링 이중화 (기존 구조 유지)
- LIVE를 끄고 과거 시점으로 이동하면 그 시각의 민원 상태를 재현한다

### 5.3 시간 필터 — 숨기지 않고 흐린다 [검증·채택]

**필터에 맞는 민원은 불투명, 맞지 않는 민원은 흐리게.** 사라지지 않는다.

관제 화면에서 객체가 없어지면 "필터에 걸린 것"과 "존재하지 않는 것"이 구분되지 않는다는 원본 논리가 우리에게도 그대로 적용된다. 특히 야간 당직처럼 인수인계가 잦은 환경에서는 맥락 유실이 사고로 이어진다.

**적용 대상**: 명령 바의 긴급·미처리 필터, 좌측 목록 필터, 시간 필터 전부.

### 5.4 재생 [채택]

- 하단 스트립에서 커서 자동 이동. 속도 1x·5x·20x
- **시연 모드(D-04)와 결합**: 긴급 민원 주입 → 배정 → 출동 재생이 이 타임라인 위에서 돈다

### 5.5 접힘 상태 [채택]

하단 스트립을 접어도 시간 범위·필터·선택 시각은 계속 지도에 적용된다.

## 6. 데이터 로딩 제약

**[검증] 대량 객체와 완전한 시간 분석은 동시에 성립하지 않는다.** 팔란티어는 1,000개를 경계로 방식을 자동 전환하고, 타일 방식에서는 시간 기능을 포기한다.

**[채택] 우리 결정**

| 레이어 | 방식 | 시간 기능 |
|---|---|---|
| 민원 핀 | 객체 기반 | **전부 지원**. 상황판은 열린 민원만 다루므로 동시 표시가 수십 건 수준 |
| 출동 인력 | 객체 기반 | 궤적·재생 지원 |
| 지적 51만 필지 | 벡터타일 | 시간 기능 없음 |
| 건축물·CCTV·시설 | 타일/정적 | 시간 기능 없음 |
| 대시보드 누적 민원 | 클러스터·열지도 | 기간 필터만 |

즉 **시간 기능은 민원·출동 레이어에만 건다.** 이 결정을 레이어별로 다르게 가져가는 것이 원본이 권하는 절충이며, 우리 데이터 성격에도 맞는다.

## 7. 디자인 토큰

**Blueprint도, 다크 배색도 쓰지 않는다.** 구조 원칙(그레이스케일은 프레임, 코어 컬러는 주의 요소, 확장 컬러는 데이터 전용)만 채택하고, 값은 이미 확정한 화성시 규격을 유지한다. 행안부 제안을 염두에 두면 KRDS 준수가 더 중요하다.

### 7.1 프레임 — 라이트 [채택]

```css
--bg:        #F7F9FC;   /* 앱 배경 */
--surface:   #FFFFFF;   /* 패널·카드 */
--line:      #E3EDF7;   /* 경계 */
--ink:       #121314;   /* 본문 */
--muted:     #5F758F;   /* 보조 */
--dim:       #8D9299;   /* 비활성 */

--hs-blue:   #1D4994;   /* 기본·제목·주요 버튼 */
--hs-blue-d: #12305F;
--hs-orange: #F07B27;   /* 강조·행동 유도 */
```

### 7.2 상태색 — 인코딩 전용 [채택]

```css
--urgent: #D63B1F;   /* 긴급 */
--prog:   #F5A623;   /* 처리중 */
--done:   #2B7DE0;   /* 완료 */
--ok:     #127A50;   /* 정상·기한 내 */
--plan:   #7A8CA0;   /* 대기·예정 */
```

### 7.3 야간모드 [채택]

기본 화면은 라이트다. **야간 근무용 어두운 배색은 기존 야간모드 토글로만** 제공한다(21시~02시 자동 전환 유지). 이때 `design.md`의 HUD 토큰(네이비 `#0a1628`, 사이언 `#38bdf8`, 글로우)을 쓴다.

즉 다크는 **선택 가능한 한 가지 모드**이지 기본값이 아니다.

### 7.4 타이포·간격 [채택]

```css
--font: "Pretendard Variable", Pretendard;
--mono: ui-monospace, Consolas;   /* 시각·좌표·수치 */

/* 글자 — KRDS 6단계 */
12px 보조·타임스탬프 · 13px 목록 부가 · 15px 본문
17px 카드 제목 · 22px 화면 제목 · 30px 지표 숫자

/* 간격 — 7값만 */
4 · 8 · 12 · 16 · 24 · 32 · 48

/* 형태 */
radius 4(배지) 8(카드·입력) 12(모바일 버튼) 16(시트)
버튼 높이 32(보조) 40(기본) 48(주요·모바일)
```

**숫자는 `font-variant-numeric: tabular-nums`.** 시각·건수가 흔들리면 관제 화면이 아니다.

### 7.5 모션 [채택]

- 전환 0.2s ease
- 긴급 펄스 2s 주기, **긴급 미배정에만**
- `prefers-reduced-motion: reduce`에서 전부 제거

## 8. 액션 (조치)

원본은 Selection 패널에서 온톨로지 액션을 실행한다. 우리 대응:

| 액션 | 대상 | 결과 |
|---|---|---|
| 인력 투입 | 최근접 가용인력 | 출동 궤적 생성, 시민 화면 단계 전환 |
| 문자 인계 | 담당 용역업체 | 처리요청 발송, 상태 처리중 |
| 현장 확인 | — | 단계 진행 |
| 종결 | — | 상황판 제거 + 대시보드 이관. 인력 미투입 시 확인 절차 |
| 부서 변경 | 배정 결과 | 변경 이력 기록(학습 자료) |
| 조치지시 상신 | 급증 탐지 건 | 시장 조치지시 화면(#cmd)으로 |

**모든 액션은 이력에 남는다.** 누가·언제·무엇을. 감사 대응이자 다음 배정을 개선하는 자료다.

### 9.1 채택하는 규약

| 동작 | 결과 |
|---|---|

### 9.2 필터 가시성 [채택]

명령 바 필터가 걸려 있으면 **지도 위에도 그 사실이 보여야 한다.** 필터 칩이 켜진 상태로 남고, 흐려진 객체 수를 함께 표시한다. "왜 안 보이지"가 생기지 않게 한다.
