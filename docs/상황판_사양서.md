# 상황판_사양서.md

당직자 상황판(`#duty`) 재구축 사양 — 도와드림QR

> 이 문서대로 화면을 **한 번에 다시 만든다.** 부분 수정을 누적하지 않는다.
> 기능(함수·API·데이터 처리)은 기존 것을 그대로 쓰고 **껍데기만 교체**한다.
> 함께 볼 것: `design_console.md`(구조 원칙) · `행정조직도.md`(소속·명칭) · `UIUX_레퍼런스와_치수체계.html`(치수)

---

## 0. 전제

1. **라이트 톤이다.** 다크 시도는 철회했다. 화성시 색(#1D4994 / #F07B27) + KRDS 치수.
2. **페이지 전체 스크롤이 없다.** 각 구획이 자기 안에서만 스크롤한다.
3. **화면 예산을 넘기지 않는다.** 아래 상한을 넘는 요소를 넣으려면 다른 것을 뺀다. 이 규칙이 이번 재구축의 핵심이다.
4. **당직자가 상시로 보는 것은 셋이다** — 민원 현황 · 인력 현황 · 실시간 뉴스. 이 셋은 탭으로 숨기지 않고 한 화면에 같이 둔다.
5. 기능을 새로 만들지 않는다. 이미 있는 것을 재배치한다. 예외는 6장에 명시한 사진 조회다.

## 2. 헤더 (1줄, 48px)

좌→우 배치. **현재 3줄로 나뉘어 있는 것을 하나로 합친다.**

| 요소 | 내용 |
|---|---|
| 로고 | 화성특례시 마크 + `당직 업무 플랫폼` |
| 화면 탭 | 상황판 · 대시보드 · 기동단 · 조치지시 · 민원창구 (5개) |
| 검색 | `Ctrl K` |
| 필터 | 전체 · 긴급 · 미처리 |
| LIVE | 연결 상태 점 + `LIVE` |
| 시간 범위 | 1시간 · 6시간 · 24시간 |
| 시계 | `09:38:45` (1개만) |
| 소속 | 선택 결과만 짧게 (3장) |

**제거**: 별도의 조직도 줄, 중복 시계, 중복 소속 표시, `내부망` 배지.

### 2.1 소속 선택 (3단계)

헤더 우측 소속 버튼을 누르면 선택창이 뜬다.

| 1차 | 2차 | 권한 범위 |
|---|---|---|
| **상황실** | 시장 · 부시장 · 재난안전상황실 | 전체 + 조치지시(`#cmd`) |
| **부서** | 본청·구청 부서 목록 | 부서 소관 전건 |
| **행정복지센터** | 29개 목록 | 관내 전체 |

- 목록은 `행정조직도.md` 기준. 검색 입력으로 좁힐 수 있게 한다.
- 헤더에는 **결과만** 표시(`팔탄면행정복지센터`). 경로를 늘어놓지 않는다.
- 선택값 저장, 다음 접속 시 그 범위로 시작.
- 명칭은 반드시 `○○행정복지센터`. `읍사무소·면사무소·동주민센터` 표기 금지.

## 3. 좌측 패널 (320px)

**세 구획이 세로로 쌓인다. 탭이 아니다.** 각 구획에 머리글이 있고 접을 수 있으나, 민원 목록은 접을 수 없다.

### 3.1 민원 현황 (높이 55%)

**머리글 한 줄** — 숫자 4개만. 카드로 만들지 않는다.
```
미처리 14 · 긴급 3 · 출동중 2 · 오늘완료 11
```
- 글자 12px, 숫자만 진하게. 높이 24px 이내.
- **제거**: `138 금일 접수` 대형 카드, 통계 4칸 박스, `창구 3 · 당직 8`, `내려받기` 링크.

**목록 구획 3개** — 고정 머리글 + 건수, 스크롤해도 머리글 유지.

| 구획 | 규칙 |
|---|---|
| **긴급** | 항상 최상단. 접기 불가. 미배정 건은 펄스 |
| **일반** | 최신순 |
| **처리중** | 접기 가능 |

완료 건은 목록에서 제외(대시보드 이관, 기존 규칙).

**목록 행** — 높이 52px, 2줄 구성.
```
[상태색 바] 21:14  수질오염 · 소하천 폐수     [📷] [긴급]
            만세구 마도 일원 · #13668
```
- 1줄: 시각(mono) · 유형 · 사진 아이콘(있을 때만) · 긴급 배지
- 2줄: 위치 · 접수번호
- 좌측 3px 상태색 바: 긴급 `#D63B1F` / 처리중 `#F5A623` / 대기 `#7A8CA0`
- **처리구분(즉시·단기·중장기)은 여기 표시하지 않는다.** 기동단 화면 전용이다.
- 클릭 → 지도 포커스 + 우측 상세. 재클릭 → 선택 해제.

### 3.2 인력 현황 (높이 20%)

```
현재 근무대 · 주말 주간(09~18)          [편성표]
만세구청      가용 2 · 출동 1
효행구청      가용 3 · 출동 0
병점구청      가용 2 · 출동 1
동탄구청      가용 4 · 출동 0
```
- 한 줄에 기관명 + 가용/출동. **세로로 글자가 쪼개지지 않게** 폭을 확보한다(현재 버그).
- 편성표는 버튼 → 모달. 패널 안에 펼치지 않는다.

### 3.3 실시간 뉴스 (높이 25%)

```
09:31  화성시, 호우 예비특보 발효          연합
09:12  동탄 지하차도 통제 해제              경기일보
```
- 시각 + 제목 1줄 + 출처. 요약문 없음.
- 제목이 길면 말줄임. 클릭 → 새 창.
- 출처: 기존 `/api/naver` 유지.

## 4. 지도

### 4.1 도구 배치

| 위치 | 내용 | 상한 |
|---|---|---|
| 좌상단 칩 | 민원 · 행사인파 · CCTV · 돌발상황 · 지적 + `전체` | **한 줄 6개** |
| 우상단 세로 | 전체화면 · 항공 · 기상 · 야간 · 탐색 · 내위치 | 6개, 32px 정사각 |
| 좌하단 배지 | `23°C 맑음 · PM10 좋음` | 1개, 클릭 시 상세 |
| 우하단 | 축척 | — |

- `전체` 칩 → 레이어 전체 목록이 **지도 위 오버레이 패널**로 열린다(좌측 패널을 차지하지 않는다).
- 칩이 두 줄로 넘치면 안 된다. 넘칠 요소는 `전체` 안으로.
- **기상 오버레이는 현행 유지.** 켜졌을 때만 `↩ 상황판으로` 버튼이 우상단 묶음에 추가된다.

### 4.2 토글 상태 표기 【현재 반대로 되어 있음】

| 상태 | 표기 |
|---|---|
| 켜짐 | 진한 배경(#1D4994) + 흰 글자 + `aria-pressed="true"` |
| 꺼짐 | 흰 배경 + 회색 글자 + 연한 테두리 |

### 4.3 마커

- 모양 = 유형 / **색 = 긴급도·상태만** / 크기 = 중복 신고 수 / 테두리 = 선택
- 부서·관할구를 색으로 나누지 않는다.
- 펄스는 **긴급 미배정**에만.
- 완료 건은 표시하지 않는다.

### 4.4 출동 인력 표현 【확정 사양 — 현재 미적용】

배달 앱의 라이더 추적 방식을 옮긴 것. 시민 화면(`#track`)과 **같은 규칙을 상황판에도 적용**한다. 지금은 예전 방식 그대로라 반영이 필요하다.

**항상 적용하는 4가지**

| 기법 | 내용 |
|---|---|
| 부드러운 이동 | 위치 정보는 몇 초 간격으로 들어오지만 그대로 찍으면 순간이동한다. 두 지점 사이를 보간해 60fps로 채운다 |
| 진행 방향 회전 | 직전 위치와 현재 위치의 각도로 아이콘을 돌린다. 어디로 가는 중인지 즉시 읽힌다 |
| 지나온 길 흐리게 | 경로 전체를 회색으로 깔고, 진행한 만큼 진한 선이 덮는다. 남은 거리가 선 길이로 보인다 |
| 도착 임박 표시 | 잔여 18% 구간에서 신고 지점 마커가 맥박처럼 커졌다 작아진다 |

**선택 — 화면 자동 추적**

- 지도 우상단 도구에 `따라가기` 토글. **상황판은 기본 꺼짐**(여러 건을 동시에 봐야 하므로), 시민 화면은 기본 켜짐.
- 켜져 있어도 **지도를 직접 조작하면 즉시 해제**되고 `다시 따라가기` 버튼이 뜬다. 다른 지역 확인 중에 화면이 끌려가면 안 된다.

**자동 — 신호 끊김 표시**

- 위치가 일정 시간 갱신되지 않으면 마커를 흐리게 하고 라벨을 `위치 확인 중`으로 바꾼다. 다시 들어오면 복귀.
- **토글이 아니라 상태다.** 현장은 음영지역이 많아 이게 없으면 멈춘 화면이 고장으로 오해된다.

**표시 요소**

- 이동 마커 옆 라벨: `향남 순찰조 · 2.4km` (조직 단위. 개인 이름·연락처 금지)
- 우측 패널 처리 이력에 도착 예정 시각 표시. **남은 시간이 아니라 시각**(`21:31`), 1분 미만이면 `곧 도착`
- 도착 예정은 경로 탐색(OSRM) 응답의 소요시간을 사용한다. 이미 받아오고 있으므로 꺼내 쓰기만 하면 된다

**시민 화면과의 동기화**

- 지도 진행률과 시민 화면 진행 막대는 **같은 값**을 쓴다. 따로 놀면 신뢰가 무너진다
- 단계는 접수 · 출동 · 현장확인 · 완료 4칸 고정
- 시민에게 보내는 범위: 담당 조직명 · 남은 거리 · 도착 예정 시각까지. 좌표는 소수점 3자리로 뭉갠다

**참고**: `인력이동_표현_레퍼런스.html` — 각 기법을 켜고 끄며 비교할 수 있는 데모

## 5. 우측 패널 — 기본 340px / 선택 시 640px 확장

민원을 선택하면 **패널이 넓어진다.** 지도 위에 모달을 띄우지 않는다.

### 5.1 왜 확장인가

340px에 조치 안내를 다 넣기엔 좁고, 그렇다고 지도 중앙에 모달을 띄우면 **출동 상황을 보면서 지시할 수 없다.** 관제의 기본은 지도와 상세를 동시에 보는 것이다. 패널을 넓히면 지도가 줄어들 뿐 사라지지 않는다.

### 5.2 동작

| 상태 | 폭 | 내용 |
|---|---|---|
| 미선택 | 340px | 대기 안내, 최근 처리 요약 |
| 선택 | **640px** | 2열 상세 (5.3) |
| 복귀 | 340px | 닫기(✕) 또는 같은 민원 재클릭 |

- 지도는 그만큼 줄되 **최소 폭 480px를 유지**한다. 그 아래로 내려가면 확장하지 않는다.
- 확장·복귀는 0.2s 전환. `prefers-reduced-motion`에서는 즉시.
- **모달·백드롭을 쓰지 않는다.** 지도는 항상 보인다.
- 화면 폭 1280px 미만에서는 확장 대신 **전체 폭 오버레이**로 전환하고, 그때만 백드롭을 깐다.

### 5.3 확장 시 2열 구성

| 좌열 (조치) | 우열 (정보) |
|---|---|
| 헤더 — 접수번호·유형·위치·상태 | 현장 사진 (신고 / 조치 전 / 조치 후) |
| **조치 버튼 4개** — 인력 투입·문자 인계·현장 확인·종결 | 속성 — 접수시각·긴급도·소관·처리주체·도로등급·좌표 |
| 긴급 대응 안내 (긴급 건만) | AI 분석 — 유사 민원·급증 판정·배정 근거·확신도 |
| 담당 연락처 | 대응 매뉴얼 요약 (접힘) |
| — | 처리 이력 |

- **조치 버튼은 스크롤과 무관하게 항상 보이는 위치에 고정**한다. 급할 때 찾아 내려가면 안 된다.
- 긴급 대응 안내는 붉은 한 줄로 요약한다. 예: `인명·안전 위험 시 119/112 즉시 공동대응 → 재난안전상황실 ☎5189-2119`
- 배정 확신이 낮으면 헤더 아래 경고 한 줄(`배정 확신 35% · 확인 필요`).
- **같은 문장을 제목·부제·전화로 반복하지 않는다.** 현재 '어디로 연락하나' 블록에 3중 반복이 있다.

### 5.4 접힘 규칙 (미선택·좁은 폭일 때)

펼침은 한 번에 하나. 기본 펼침은 **사진**, 기본 접힘은 **대응 매뉴얼·처리 이력**이다.

### 5.5 모달로 남기는 것

별도 화면이 필요한 것만 모달로 띄운다.

- 매뉴얼 전문 검색
- 편성표
- 문자 인계 작성
- 인력 선택 변경

모달 규칙: 동시에 하나만, 백드롭 필수, `Esc`·백드롭 클릭으로 닫힘, 최대 폭 560px·최대 높이 80vh(초과 시 내부 스크롤).

## 6. 사진 표시 【신규 — 지금 아무 데서도 안 보임】

### 6.1 저장

- Supabase Storage 버킷: `photos/{민원번호}/report_{n}.jpg` · `before.jpg` · `after.jpg`
- `complaints` 컬럼 추가: `photo_report(jsonb)` `photo_before` `photo_after` `photo_public(bool)` `result_type` `result_memo` `reported_by` `reported_at` `report_lat` `report_lng`
- 업로드 전 리사이즈: 장변 1600px, JPEG 0.8, 장당 500KB 이하 목표
- 전송 실패 시 기기 대기 후 자동 재전송. 시민 화면에 `사진 전송 중` 표시
- 자동 유입 시나리오에는 사진을 넣지 않는다

### 6.2 표시

| 위치 | 내용 |
|---|---|
| 우측 패널 3번 섹션 | `신고` → `조치 전` → `조치 후` 가로 3칸. 클릭 시 확대 |
| 좌측 목록 행 | 사진 있는 건에 📷 아이콘 |
| 기동단 작업판 | 카드에 신고 사진 썸네일 |
| 읍면동 결과보고 | 조치 후 사진 썸네일 |
| 시민 처리 현황 | 본인 신고 사진 + 완료 시 조치 후(`photo_public=true`만) |
| 대시보드 완료 이력 | 행 클릭 시 상세에 포함 |

- 라벨을 반드시 붙인다. 어느 쪽이 처리 후인지 헷갈리면 증빙이 안 된다.
- 사진 아래 촬영 시각 + 신고 지점으로부터의 거리.
- 없으면 `사진 없음`을 명시. 빈칸 금지.
- hwpx 일일보고·민원접수서에 조치 후 사진 삽입 가능하게 한다.

## 13. 검증 (1440×900)

- [ ] 헤더가 1줄이고 시계·소속이 각 1개
- [ ] 세로 스크롤이 생기지 않음
- [ ] 지도 폭 560px 이상
- [ ] 좌측에 민원 목록 10건 이상 + 인력 + 뉴스가 동시에 보임
- [ ] 긴급 건이 최상단 구획에 모여 있음
- [ ] 레이어 토글 켜짐이 진하고 꺼짐이 흐림
- [ ] 지도 칩이 한 줄
- [ ] 하단 스트립과 지도가 겹치지 않음
- [ ] 민원 선택 시 우측이 640px로 확장되고 지도가 계속 보임
- [ ] 지도 위에 모달이 뜨지 않음 (매뉴얼 검색 등 예외만)
- [ ] 지도 도구가 패널 위로 튀어나오지 않음
- [ ] 시간대별 막대 그래프가 정상 스케일
- [ ] 사진이 우측 패널·목록·시민 화면에서 보임
- [ ] 인력 투입 시 마커가 부드럽게 이동하고 진행 방향으로 회전함
- [ ] 지나온 경로가 흐려지고 도착 임박 시 신고 지점이 맥박침
- [ ] `따라가기` 토글이 있고, 지도를 만지면 자동 해제됨
- [ ] 도착 예정이 시각으로 표시되고 시민 화면과 값이 같음
- [ ] `팔탄면행정복지센터`처럼 표기됨
- [ ] 소속 선택이 3단계로 동작
- [ ] `BUILD_VER` 갱신됨

## 14. 작업 방식

1. `redesign` 브랜치에서 진행. `main`은 건드리지 않는다.
2. 상황판 화면(`#duty`)의 마크업·스타일을 이 사양대로 **새로 작성해 교체**한다. 기존 함수·API 호출은 재사용한다.
3. 6장 사진은 DB 스키마 변경이 필요하다. 마이그레이션 SQL을 별도 파일로 만들어 사용자에게 실행을 요청할 것.
4. 커밋 전 검증 3종(JS 문법 · 파일 크기 · 핵심 앵커) 수행.
5. 완료 후 13장 체크리스트 결과를 함께 보고한다.
