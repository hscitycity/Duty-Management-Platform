# 상황판_사양서.md (v3)

당직자 상황판 재구축 사양 — 도와드림QR

> **v1 실패를 반영한 개정판이다.** v1은 "구획별 고정 높이"를 정했으나 담을 내용이 그 높이에 맞지 않아
> 모든 요소가 납작해지고 스크롤바가 다섯 개 생겼다. 이번에는 **화면을 쪼개서** 각 화면이 한 가지 일만 하게 한다.
> 함께 볼 것: `기동단_사양서.md` · `행정조직도.md` · `design_console.md`

## 0. 이번 개정의 원칙

**① 한 화면은 한 가지 일만 한다.**
v1의 상황판은 목록·지도·상세·접수·일지·인력·뉴스·타임라인을 전부 담았다. 그래서 접수 입력창이 납작해지고 일지는 열리지도 않았다. 접수와 일지는 **별도 화면으로 뺀다.**

**② 내용이 안 들어가면 높이를 줄이지 말고 항목을 뺀다.**
v1이 무너진 지점이다. 고정 높이에 내용을 욱여넣지 않는다. 6장의 「담지 않는 것」을 지킨다.

**③ 스크롤 영역은 화면당 최대 2개.**
현재 다섯 개다. 좌측 목록 하나, 우측 상세 하나. 그 외 구획은 스크롤 없이 전부 보이거나, 안 보이면 항목을 줄인다.

**④ 글자 크기는 6단계만.**
12 · 13 · 15 · 17 · 22 · 30px. 그 외 금지. 요소별 지정은 8장.

**⑤ 라벨 없는 숫자·버튼을 만들지 않는다.**
`1시간 6시간 24시간`이 무엇인지, `흐림 11건`이 무엇인지 화면만 보고 알 수 있어야 한다.

## 2. 상황판 골격 (1440×900 기준)

```
┌──────────────────────────────────────────────────────────────┐
│ 헤더 48px  (모든 화면 공통 부품)                                 │
├─◀─────────────┬──────────────────────────┬──────────────▶───┤
│ 좌측 320       │          지도             │ 우측 340         │
│ (접기 가능)     │       (잔여 전체)          │ (접기 가능)       │
│ 분류 카드 3    │  도구는 지도 위 오버레이     │ 선택 시 640      │
│ + 민원 목록    │                          │ 5가지 상태(6장)   │
│    852px      │         852px            │      852px       │
└───────────────┴──────────────────────────┴──────────────────┘
```

높이: `900 − 48(헤더) = 852px`. **하단 스트립은 없앤다.** v2에서 계획했던 인력·뉴스·지표는 일반현황(`#info`)으로 옮긴다. 좁은 칸에 넣어 판독이 안 되던 문제를 자리를 옮겨 해결한다.

### 2.1 사이드바 접기

| 대상 | 동작 |
|---|---|
| 좌측 | 경계의 `◀` 버튼으로 접힘. 24px 세로 탭만 남고 지도가 확장 |
| 우측 | 경계의 `▶` 버튼으로 접힘. 동일 |

- 접힘 상태를 저장해 다음 접속 시 유지한다.
- 좌측을 접어도 지도 마커 클릭으로 민원을 선택할 수 있어야 한다.

### 2.2 폭 조절

- 좌측·지도, 지도·우측 **경계를 마우스로 끌어 폭을 조절**한다.
- 범위: 좌측 260~480px, 우측 300~720px. **지도는 최소 480px 유지**하며 그보다 좁아지는 드래그는 멈춘다.
- 조절값을 저장한다. 경계 우클릭 메뉴에 초기화를 둔다.
- 드래그를 놓는 순간 `map.invalidateSize()`를 호출해 타일 깨짐을 막는다.

## 3. 헤더 (48px, 1줄)

```
[로고]  민원현황  일반현황  처리결과  교통·도로 기동단 │ 🔍 민원검색 │ 표시: 일반 · 긴급 · 교통·도로 기동단 │ ● LIVE │ 10:14:29 │ 👤 소속 │ [조치지시] [24시간 민원접수창구]
```

### 3.1 화면 이름 통일

| 주소 | 기존 이름 | **바꿀 이름** |
|---|---|---|
| `#duty` | 당직자 상황판 | **민원현황** |
| `#dash` | 종합현황 대시보드 | **처리결과** |
| `#road` | 신속기동단 작업판 | **교통·도로 기동단** |
| `#info` | (신설) | 일반현황 |

화면·문서·시나리오 전부에서 이 이름으로 교체한다.
※ 기동단은 정식 명칭이 「교통·도로민원 신속처리 기동단」이므로 축약형에 가운뎃점을 유지한다(`기동단_사양서.md` 0장). 뺄지 여부는 확인 후 결정.

### 3.2 좌측 탭 (4개)

`민원현황 · 일반현황 · 처리결과 · 교통·도로 기동단`

### 3.2-1 헤더는 공통 부품으로 만든다 【중요】

현재 화면마다 헤더를 따로 그려서 민원현황만 새 헤더이고 나머지는 옛 헤더(로고+부제+옛 탭명+조직도 줄+당직자 줄)가 남아 있다.

- **헤더를 한 곳에서 그리는 함수**(`renderHeader` 등)로 만들고 모든 화면이 호출한다. 화면별 개별 헤더 마크업을 전부 제거한다.
- 화면별 차이는 **인자로만** 처리한다.
  - 시민·업체 화면(`#cit` `#track` `#done`) — 탭·필터·소속·조치지시 **숨김**. 로고와 화면명만. 내부 정보를 외부에 노출하지 않는다.
  - 그 외 — 전체 표시
- **제거**: 로고 옆 부제(`재난안전상황실(5층)…`), 조직도 줄, 당직자 별도 줄, 옛 탭 이름
- 화면 전환은 헤더 탭으로만. 화면 안에 또 다른 전환 버튼을 두지 않는다.

### 3.3 우측 별도 버튼 (2개)

탭과 성격이 다르므로 **오른쪽 끝에 따로 뺀다.**

| 버튼 | 색 | 이유 |
|---|---|---|
| **24시간 민원접수창구** | **밝은 노란색** (배경 `#FFD84D`, 글자 `#3A2E00`) | 시민이 보는 화면. 내부 업무 탭과 성격이 다르다 |
| **조치지시** | 적색 계열 (`#D63B1F` 테두리, 급증 시 채움) | 상황실 권한 전용. 급증 탐지 시에만 활성 |

- 두 버튼은 탭 묶음과 **세로 구분선으로 분리**한다.
- 조치지시는 상황실 소속이 아니면 흐리게 표시하고 눌러도 안내만 뜬다.
- 급증 탐지 중이면 조치지시 버튼에 건수 배지 + 점멸(최고 심각도에만).
- 24시간 민원접수창구는 **새 창으로** 연다(당직 화면을 잃지 않게).

### 3.4 검색·필터

| 요소 | 규칙 |
|---|---|
| **민원검색** | 문구를 `🔍 민원검색`으로. `Ctrl K`는 툴팁·단축키 안내로만 표시하고 버튼 문구로 쓰지 않는다 |
| **표시 필터** | `일반 · 긴급 · 교통·도로 기동단` 3개. **좌측 분류 카드와 같은 상태를 공유한다.** 한쪽을 바꾸면 다른 쪽도 함께 바뀐다 |
| **범위(1시간·6시간·24시간)** | **제거.** 열린 민원을 다루는 화면이므로 시간 범위를 나눌 이유가 없다 |
| 제거 대상 | 기존 `전체 · 긴급 · 미처리` 필터(분류와 축이 겹친다), `필터` `범위` 라벨 |

- 필터와 좌측 카드는 **같은 축이므로 둘 중 하나만 조작해도 된다.** 두 개를 따로 두되 상태는 하나로 묶는다.
- 필터 적용 시 지도 마커는 숨기지 않고 흐리게. 그 아래 `필터 제외 N건 — 흐리게 표시 [전체 보기]`.

### 3.5 나머지

- 시계·소속은 각 1개. 조직도 줄·중복 표시 제거.
- 소속 선택은 3단계(상황실 / 부서 / 행정복지센터). 목록 출처는 `행정조직도.md`이며, 분장사무 데이터로 목록을 만들지 않는다.

## 4. 좌측 — 민원 목록 (320px)

### 4.1 상단 — 분류 카드 3개

목록을 한 덩어리에 쌓지 않는다. **입구를 셋으로 나누고 하나씩 본다.**

```
┌──────────┐ ┌──────────┐ ┌──────────┐
│  긴급    │ │  일반    │ │ 교통·도로 │
│    8     │ │   19     │ │   12     │
└──────────┘ └──────────┘ └──────────┘
```

| 카드 | 담는 것 | 색 |
|---|---|---|
| **긴급민원** | 긴급도 = 긴급 | 적색 `#D63B1F` |
| **일반민원** | 긴급도 = 일반 | 파랑 `#1D4994` |
| **교통·도로 기동단** | 기동단 이관 건 | 주황 `#F07B27` |

**긴급과 기동단은 축이 다르다.**
- `긴급` = 우선순위 · `일반` = 우선순위 · `교통·도로 기동단` = **담당 주체**
- 도로 함몰처럼 **긴급이면서 기동단 건**일 수 있다. 이때는 **두 카드에 모두 집계·표시**한다.
- 카드를 상호배타로 만들지 않는다. 긴급 카드에서는 `기동단` 배지가, 기동단 카드에서는 `긴급` 배지가 붙는다.
- 건수 합계가 전체 건수와 다를 수 있다. 하단에 `※ 긴급·기동단 중복 집계` 안내 한 줄.

- 카드 높이 64px, 3등분. 라벨 12px + 건수 22px.
- 선택된 카드는 진한 배경 + 흰 글자. 나머지는 흰 배경 + 색 테두리.
- **한 번에 하나만 선택된다.** 아래 목록이 그 분류로 바뀐다.
- 기본 선택은 **긴급민원**. 건수가 0이면 일반민원으로.
- 건수는 실시간 갱신. 새 건이 들어오면 해당 카드에 잠깐 강조 표시.
- **교통·도로 기동단 카드는 건수만 보여주고, 클릭 시 목록을 띄운다.**
  상세 처리는 `#road` 화면에서 한다(목록 하단에 `기동단 작업판 열기` 링크).

### 4.2 그 아래 한 줄 (24px)

```
미처리 19 · 출동중 2 · 오늘완료 11               [CSV]
```
- 숫자 15px, 라벨 12px. 카드·박스로 만들지 않는다.
- 필터가 걸려 있으면 12px 한 줄 추가: `필터 제외 11건 — 흐리게 표시  [전체 보기]`
- **제거**: `시장 · 20건 (우리 0 · 타 부서 20)` → 소속 버튼 툴팁으로

### 4.3 목록 (약 620px, 스크롤 1개)

선택한 분류의 민원만 최신순으로 나열한다. **구획 머리글이 없다** — 이미 분류가 정해져 있으므로.

**카드 = 52px 고정, 2줄.**
```
10:05  낙하 위험물 · 안전재난        📷 신규
효행구 봉담 일원 · #13675
```
- 1줄: 시각 12px mono · 유형 13px · 아이콘 · 상태 배지(최대 2개)
- 2줄: 위치·번호 12px 회색
- **내용 요약 문장을 카드에 넣지 않는다.** 우측 상세에만 둔다.
- 넘치면 말줄임. 줄바꿈 금지.
- 좌측 3px 상태색 바: 신규접수 / 처리중 / 인계됨
- 처리구분(즉시·단기·중장기)은 **교통·도로 분류에서만** 배지로 표시한다.

**표시 개수**: 620px에서 카드 **10개 이상**이 보여야 한다.

**목록이 비면**: `해당 분류에 열린 민원이 없습니다`를 회색으로. 빈 화면으로 두지 않는다.

### 4.4 지도와의 연동

- 분류를 바꾸면 **지도 마커도 그 분류만 진하게** 표시한다. 나머지는 흐리게(숨기지 않는다).
- 목록에서 민원을 고르면 지도가 그 위치로 이동하고 우측 상세가 열린다.

## 5. 지도

### 5.1 도구

| 위치 | 내용 | 상한 |
|---|---|---|
| 좌상단 칩 | 민원·행사인파·CCTV·돌발상황·지적 + `전체` | 한 줄 6개 |
| 우상단 세로 | 항공·기상·야간·탐색·내위치·전체화면 | **6개 상한**, 32px 알약, 아이콘 + 라벨 |
| 좌하단 | `23°C 맑음 · PM10 좋음` 배지 | 1개 |
| 우하단 | 축척 | — |

- `전체` → 레이어 목록이 **지도 위 오버레이 패널**로 (좌측을 차지하지 않는다)
- **우상단 도구는 알약 모양**으로 한다. 높이 32px · 좌우 여백 12px · 폭 auto · 아이콘 + 라벨(`🛰 항공`).
- **여섯 개를 넘기지 않는다.** 일곱 번째가 필요하면 무엇을 뺄지 함께 정한다(§10.1 규칙 5).
  `🛵 따라가기`·`🏷️ 설명 라벨`은 표시 옵션이므로 **레이어 오버레이 패널**로 옮겼다.
- **같은 일을 하는 버튼을 Leaflet 컨트롤로 또 만들지 않는다.** `id` 가 둘이 되어 상태 표시가 어긋난다.
  (실제로 `panBtn` 이 도구 묶음과 지도 컨트롤에 각각 있어 한쪽이 늘 꺼진 것처럼 보였다.)
- **민원 레이어를 꺼도 선택한 민원 하나는 지도에 표시한다.** 목록에서 고른 건이 지도에서 사라지면 위치를 확인할 수 없다. 선택 마커는 레이어 토글의 영향을 받지 않는다.
- 토글: 켜짐 = 진한 배경 + 흰 글자 / 꺼짐 = 흰 배경 + 회색. **현재 반대다.**
- 마커 색 = 긴급도·상태만. 부서·관할구를 색으로 나누지 않는다.
- **마커 아이콘이 지금 과하게 크고 장식적이다. 28px 이내 단순한 형태로.**

### 5.2 출동 인력 표현

- 항상 적용: 부드러운 이동(보간) · 진행 방향 회전 · 지나온 길 흐리게 · 도착 임박 표시(잔여 18%)
- 선택: `따라가기` 토글 — 상황판 기본 꺼짐, 지도 조작 시 자동 해제 + `다시 따라가기`
- 자동: 위치 갱신 끊기면 마커 흐림 + `위치 확인 중` (토글 아님)
- 라벨: `향남 순찰조 · 2.4km` — 조직 단위. 개인 이름·연락처 금지
- 도착 예정: **시각으로**(`21:31`), 1분 미만은 `곧 도착`. OSRM 응답의 소요시간 사용
- 시민 화면 진행 막대와 **같은 값**을 쓴다

## 6. 우측 패널 — 5가지 상태

우측은 상황에 따라 다섯 가지로 바뀐다. **한 번에 하나만.** 여러 일을 한 화면에 겹치지 않는다.

| 상태 | 폭 | 전환 |
|---|---|---|
| **① 기본** | 340px | 아무것도 선택하지 않은 상태 |
| **② 민원 상세** | 640px | 목록·마커에서 민원 선택 |
| **③ 접수 입력** | 640px | 접수 버튼 클릭 |
| **④ 일반현황** | 640px | 헤더 `일반현황` 탭 |
| **⑤ 기동단 안내** | 640px | `#road`에서 [기동단이란?] 클릭 |

- 상세를 보다 접수를 누르면 상세는 닫힌다. 반대도 같다.
- ⑤는 잠깐 겹쳐 보는 안내이므로 **선택한 민원을 풀지 않는다.** 닫으면 이전 상태로 돌아온다.
- 확장 시 지도는 줄되 **최소 480px 유지**.
- 1280px 미만에서는 확장 대신 전체 폭 오버레이 + 백드롭.

### 6.1 ① 기본 — 접수 입구 3개

```
목록이나 지도에서 민원을 고르세요.

┌───────────────────────┐
│  📝 일반민원 접수       │  당직자·타 부서 직원
├───────────────────────┤
│  🚧 교통·도로 기동단 접수 │  기동단 전담 인력
├───────────────────────┤
│  📕 재난상황일지 작성    │  재난안전상황실 직원
└───────────────────────┘

최근 처리
09:16  하수도 막힘 · 향남읍
```

**이 세 입구로 화성시 민원이 전부 커버된다.** 버튼 높이 56px, 라벨 15px + 대상 12px.

### 6.2 ② 민원 상세

민원을 고르면 640px로 펼쳐진다. **모든 구획은 펼침이 기본이다.** 토글을 눌러야 보이게 하지 않는다.

**상단 — 조치 4구획** (항상 보이는 위치에 고정)

| 구획 | 내용 |
|---|---|
| **현장확인** | 확인자·시각·판정, 인력 투입 |
| **용역업체 문자발송** | 업체 선택·발송·수신 확인, 조치결과 링크 동봉(7장) |
| **조치결과** | 전/후 사진, 결과 구분. **업체가 외부에서 입력한 것도 여기 표시** |
| **민원회신** | 신고인 통보 내용·시각·방법 |

각 구획은 진행 상태를 색으로 표시한다(대기 회색 / 진행 주황 / 완료 파랑).

**하단 — 세부 6구획** (이 순서 고정)

| 순서 | 구획 | 내용 |
|---|---|---|
| 1 | **민원내용** | 위치 · 문제상황 · 조치필요사항 |
| 2 | **담당부서** | AI 분석 결과 · 배정 근거 · 확신도. **처리주체 변경은 부서 목록에서 선택**(직접 입력 금지, 행정조직도 기반) |
| 3 | **담당연락처** | 부서·업체 연락처. 같은 문장을 제목·본문에 반복하지 않는다 |
| 4 | **현장사진** | 신고 / 조치 전 / 조치 후 |
| 5 | **대응매뉴얼** | 처리 순서 |
| 6 | **처리이력** | 시각이 붙은 타임라인 |

- **색을 통일한다.** 구획 머리글은 같은 크기·같은 색, 강조는 상태색만. 구획마다 다른 배경색·아이콘 색을 쓰지 않는다.
- 상세는 **한 덩어리로 스크롤**한다. 구획별 개별 스크롤 금지.
- 640px에서는 2열: 좌열 조치 4구획, 우열 세부 6구획.

### 6.3 ③ 접수 입력

접수 버튼을 누르면 640px로 펼쳐지고 **지도가 위치 지정 모드로 바뀐다.**

- 지도를 클릭하면 그 지점이 민원 위치가 된다. 주소는 역지오코딩으로 자동 채운다.
- **주소를 직접 입력하지 않아도 된다.** 교통·도로 민원도 도로 위를 클릭하면 끝난다.
- 지정 후 핀을 끌어 미세 조정 가능. 지도 상단에 `위치를 클릭하세요` 안내 띠.

**일반민원 접수** — 당직자·타 부서 직원
```
자유 기록 (AI 서기)  입력창 160px 이상
[AI로 정리하기]
정리 결과 — 유형·긴급도·위치·요약 (수정 가능)
담당  ( ) 당직 처리   ( ) 교통·도로 기동단     ← AI 제안 + 근거
[접수 등록]
```

**교통·도로 기동단 접수** — 전담 인력이 전화받으며 이어서 기록
```
통화 기록  ← 계속 이어 쓰는 큰 입력창
5개 유형 버튼 (도로파손·교통시설·불법주정차·버스불편·교통체계)
위치: 지도 클릭
접수 즉시 [안내 마감 10:56] 표시     ← 접수+60분, 기동단 사양서 5.1
[접수 등록]
```

**재난상황일지 작성** — 재난안전상황실 직원
```
자유 서술 → parseJournal 정리 결과 (수정 가능)
[일일보고 생성] [민원접수서 생성]
과거 일지 목록
```

- 등록 후 **배정된 주체의 화면으로** 이동하고 해당 건이 선택된 상태로 열린다.

### 6.4 ④ 일반현황

헤더 `일반현황` 탭을 누르면 우측에 표시된다. 좌측 목록과 지도는 그대로.

| 구획 | 내용 |
|---|---|
| **인력 현황** | 기관별 가용·출동, 근무대, 편성표 |
| **부서현황** | **행정조직도 기반.** 실·국 → 과 계층, 청사 위치, 연락처. 검색 가능 |
| **실시간 뉴스** | 시각 + 제목 + 출처 |
| **기상·대기** | 실황·특보·미세먼지 상세 |
| **처리 지표** | 미처리·긴급·평균 처리시간·기한 내 비율 |

부서현황은 `행정조직도.md`를 근거로 만든다. 분장사무 데이터로 목록을 만들지 않는다(누락 발생).

### 6.5 ⑤ 기동단 안내

교통·도로 기동단 화면(`#road`) 상단, 「교통·도로민원 신속처리 기동단 / 대표전화 1833-4088」 바로 옆의
**[기동단이란?]** 버튼을 누르면 우측 패널이 안내 상태로 바뀐다.

**모달로 띄우지 않는다.** 전화를 받으며 시민에게 설명할 때 지도와 목록을 계속 봐야 하기 때문이다.
닫기(✕) 또는 민원 선택 시 이전 상태로 복귀한다.

**구성 — 아코디언 3단, 첫 단은 펼침**

**1) 기동단이란**
도로 파손부터 교통시설 고장, 불법주정차, 버스 이용 불편까지 다양한 민원을 한 번에 접수·처리하는
통합 민원 창구. 접수된 민원은 기동단이 현장을 확인하고 분류한 뒤 관련 부서·기관과 협력해 처리.
접수 후 1시간 이내에 처리 방안을 안내.

**2) 이런 불편을 알려주세요** (5개 유형, 각각 접기)

| # | 유형 | 예시 |
|---|---|---|
| ① | 도로 파손·침하 | 포트홀, 도로 침하, 보도 파손 |
| ② | 교통시설 고장·파손 | 신호기 고장, 표지판·반사경 파손, BIS 오류 |
| ③ | 불법주정차·통행 불편 | 불법주정차, 방치 PM, 무단방치 차량 |
| ④ | 버스 이용 불편 | 무정차, 난폭운전, 배차간격, 정류장 시설 |
| ⑤ | 교통체계 개선 | 도로 혼잡, 신호체계 개선, 버스노선 개선 |

**3) 이렇게 처리됩니다** (4단계)

1. **전화 한 통으로 접수** — 대표전화 1833-4088
2. **기동단 확인 및 민원 분류**
   - 즉시(24시간): 신호기·표지판·반사경·BIS 오류
   - 단기(48시간): 시설물 파손·정류장 시설 개선
   - 중장기: 도로 혼잡·신호체계·버스노선 개선
3. **처리 방안 안내** — 접수 후 1시간 이내
4. **진행 상황 및 처리 결과 안내** — 관련 부서·기관과 협력 처리

#### 데이터 관리 【중요】

5개 유형과 처리구분 기한은 `기동단_사양서.md` **3장·2장과 같은 데이터다.**
안내문·접수 유형 버튼·분류 로직이 **같은 상수를 참조**하게 한다.
따로 하드코딩하면 유형이 추가될 때 세 군데가 어긋난다.

| 화면 요소 | 참조 상수 |
|---|---|
| 안내문 5개 유형 · 접수 유형 버튼 · 분류 로직 | `ROAD_CATS` (3장) |
| 처리구분 기한 문구 | `TRIAGE_META` · `TRIAGE_MS` (2장) |
| 「접수 후 1시간 이내」 | `GUIDE_MIN` (5.1) |

#### 운영 시작일

안내 상단에 「2026년 9월 7일 운영 시작」 배지를 표시하고, **시작일이 지나면 자동으로 사라진다.**

#### 표기·디자인

- 명칭은 「교통·도로민원 신속처리 기동단」, 좁은 곳은 「교통·도로 기동단」.
- 색·글자 크기는 8장 규격을 따른다. **안내문이라고 별도 색을 쓰지 않는다.**
- 전화번호는 `tel:` 링크로 걸어 클릭 시 통화 가능하게.

## 7. 용역업체 조치결과 보고 `#done`

문자 인계 시 **처리요청과 함께 전용 링크**를 보낸다. 업체 직원이 현장에서 휴대폰으로 사진만 올리면 끝난다.

### 7.1 원칙

- **로그인·앱 설치 없음.** 시민 창구와 같은 방식이다.
- **텍스트 입력을 요구하지 않는다.** 바쁜 현장이다. 메모는 접어두고 원하는 사람만 펼친다.
- 위치·시각·업체·담당자는 링크와 사진에서 자동으로 채운다.

### 7.2 화면 (한 장)

```
① 민원 요약   유형 · 주소 · 요청사항 · 신고 사진   (읽기 전용)
② 사진 촬영   [조치 전] [조치 후]  ← 누르면 카메라 바로 열림
③ 결과 선택   (완료) (추가 작업 필요) (현장 이상 없음)
④ [전송]      높이 48px
   메모 (선택) ▾
```

### 7.3 현장 조건

- 회선이 나쁘면 자동 대기 후 재전송. 화면에는 `전송 중`만 표시
- 촬영 즉시 압축(장변 1600px, 500KB 이하 목표)
- 촬영 위치가 신고 지점과 멀면 안내만 하고 **막지 않는다**(현장 사정이 있을 수 있다)
- 처리 완료 후 링크 만료. 만료 시 `이미 처리된 민원입니다`

### 7.4 보안 제한

로그인이 없으므로 주소를 아는 사람은 열 수 있다. 그래서 다음으로 제한한다.

- 그 민원 **한 건만** 열린다. 다른 민원 조회 불가
- **신고인 개인정보를 표시하지 않는다.** 유형·주소·요청사항까지만
- 토큰은 민원별로 다르게 발급하고 만료 시각을 둔다

업체가 올린 결과는 민원 상세의 **조치결과 구획**에 그대로 표시된다.

## 8. 타이포·색·순서

| 요소 | 크기 | 굵기 |
|---|---|---|
| 화면 제목 / 지표 숫자 | 22 / 30 | 700 |
| 상세 헤더 유형명 | 17 | 700 |
| 본문·카드 유형 | 13~15 | 400~600 |
| 카드 2줄·라벨·시각 | 12 | 400 |
| 배지 | 11 | 700 |

- 줄간격 1.5, 카드 안 1.35. 숫자는 `tabular-nums`.
- **한 화면에서 6단계를 넘는 크기가 나오면 규격 위반이다.**

```css
--hs-blue:#1D4994; --hs-orange:#F07B27;
--urgent:#D63B1F; --prog:#F5A623; --done:#2B7DE0; --ok:#127A50; --plan:#7A8CA0;
간격 4·8·12·16·24·32·48   둥글기 4·8·12·16   버튼 32·40·48
z-index 0 지도 / 400 지도도구 / 600 패널 / 800 헤더 / 1000 오버레이패널 / 1400 백드롭 / 1500 모달 / 1800 토스트
```

### 8.1 z-index 는 변수로만 쓴다

값을 코드 곳곳에 숫자로 적으면 다시 어긋난다. 여덟 단계를 `:root` 변수로 선언하고 그 변수만 참조한다.

```css
:root{ --z-map:0; --z-maptool:400; --z-panel:600; --z-header:800;
       --z-overlay:1000; --z-backdrop:1400; --z-modal:1500; --z-toast:1800; --z-in:1; }
```

- `--z-in`(1)은 **구획 내부**의 겹침이다(스크롤 영역 안의 고정 머리글 등). 자기 구획 경계를 넘지 않는다.
- **Leaflet 기본 컨트롤은 z-index 800~1000 이다.** 그대로 두면 패널·헤더·모달을 덮는다.
  `.leaflet-pane` `.leaflet-top` `.leaflet-bottom` `.leaflet-control` 을 **지도 도구 단계(400)로 끌어내린다.**
- 모달이 열리면 `body.modal-on` 을 걸어 **지도 위 도구를 숨긴다.** 계층만으로는 지도 도구가 반투명 배경 위에 비쳐 보인다.
- **`.leaflet-pane` 은 덮지 않는다.** Leaflet 은 pane 마다 z-index 를 나눠 쓴다(타일 400 · 마커 600 · 팝업 700).
  한 값으로 덮으면 그 내부 순서가 평평해져 **지도 팝업이 레이어 칩과 동률이 되고 DOM 순서상 칩이 이긴다.**
  라이브러리의 계층을 사다리에 맞출 때는 **컨트롤 모서리(`.leaflet-top` `.leaflet-bottom` `.leaflet-control`)만** 건드린다.
- 지도 팝업(`.leaflet-popup-pane` 700)은 **지도 위 도구(400)보다 위**에 온다. 칩이 팝업을 가리면 내용을 읽을 수 없다.

## 10. 겹침·잘림 — 현재 확인된 것과 해결책

화면에서 반복해서 나타나는 문제다. **개별 위치 조정이 아니라 아래 원인별 규칙으로 해결한다.**

| # | 현상 | 원인 | 해결 |
|---|---|---|---|
| 1 | 좌측 인력현황·실시간뉴스가 잘리고 각자 스크롤바가 생김 | 좌측 한 칸에 목록·인력·뉴스 세 가지를 넣음 | **인력·뉴스를 일반현황(`#info`)으로 이동**(6.4). 좌측은 목록만 |
| 2 | 하단 `상세·접수·일지` 탭이 화면 아래를 가림 | 우측 패널이 좁아 하단으로 밀려남 | **우측 패널 5상태로 통합**(6장). 하단 탭·스트립 모두 제거 |
| 3 | 지도 우상단 도구가 레이어 칩 줄과 겹치고 일부가 잘림 | 칩과 도구가 같은 상단 영역을 씀 | 칩은 좌상단 한 줄, 도구는 **우상단에서 12px 아래로 내려** 세로 배치. 서로 침범 금지 |
| 4 | 지도 마커가 서로 겹쳐 덩어리로 보임 | 마커가 크고 장식적 | **28px 이내 단순 형태.** 가까운 건은 묶음 표시(개수 배지, 내부 최고 심각도 색) |
| 5 | 담당 연락처가 제목·본문에 같은 문장 2회 반복 | 템플릿에서 요약과 본문을 모두 출력 | 한 번만 표시. 업체명·담당 전화 한 줄로 |
| 6 | 우측 패널 내용이 아래에서 잘림 | 패널 안에서 여러 구획이 각자 스크롤 | 상세는 **한 덩어리로 스크롤**. 조치 버튼만 상단 고정 |
| 7 | 우측 상단 주황 원형 버튼이 패널 위에 떠 있음 | 정체 불명 요소 | 확인 후 제거하거나 라벨을 붙여 도구 묶음에 편입 |
| 8 | `타임라인` 버튼이 하단 탭과 겹침 | 하단에 두 체계가 공존 | 하단 영역 자체를 없앤다(2장) |
| 9 | 지도 우상단 도구의 글자가 버튼을 벗어남 | 32px 원형에 두 글자를 넣음 | **알약 모양으로**(5.1). 높이 32px, 폭 auto |
| 10 | 화면마다 헤더가 다름 | 화면별로 헤더를 따로 그림 | **공통 부품으로**(3.2-1) |
| 11 | 민원 레이어를 끄면 선택한 민원도 사라짐 | 선택 마커가 레이어 토글을 따름 | 선택 마커는 토글과 무관하게 표시(5.1) |

### 10.1 재발 방지 규칙

1. **떠 있는 요소는 자기 영역 안에만 있는다.** 지도 도구는 지도 안, 패널 버튼은 패널 안. 경계를 넘는 `position:fixed`를 쓰지 않는다.
2. **z-index는 8단계만**(8장). 그 외 값은 코드에서 제거한다. 지도 위 도구는 400을 넘지 않는다.
   숫자를 직접 적지 말고 8.1의 변수만 쓴다. **외부 라이브러리(Leaflet)의 기본 z-index 도 사다리 안으로 끌어온다.**
3. **스크롤 영역은 화면당 2개 이하.** 세 번째가 생기려 하면 그 구획의 내용을 줄이거나 다른 화면으로 옮긴다.
4. **고정 높이 안에 안 들어가면 항목을 뺀다.** 글자를 줄이거나 줄간격을 좁혀 욱여넣지 않는다.
5. 새 요소를 추가할 때 **무엇을 빼는지 함께 적는다.**

## 11. 검증 (1440×900 실측)

- [ ] 지도 우상단 도구가 알약 모양이고 글자가 넘치지 않으며 **6개를 넘지 않음**

## 12. 작업 방식

1. `redesign` 브랜치. `main` 금지.
2. **접수·일지 분리를 먼저** 한다. 상황판에서 두 기능을 들어내야 나머지 배치가 성립한다.
3. 그다음 상황판 셸(헤더·좌측·지도·우측·하단)을 이 사양대로 새로 작성해 교체.
4. 기능(함수·API)은 재사용. 껍데기만 교체.
5. 커밋 전 검증 3종(JS 문법·파일 크기·핵심 앵커).
6. 완료 후 **11장 체크리스트를 항목별로 측정해 보고**한다. "적용했다"가 아니라 "카드 12개가 보인다"처럼 수치로.
