# design_palantir.md

팔란티어 계열(Gaia / Foundry Map) 지도 기반 관제 콘솔 디자인 스펙

---

## 0. 출처 표기 규칙

이 문서의 모든 항목에는 근거 등급이 붙는다. 구현 시 판단 기준이 달라지므로 반드시 확인할 것.

| 표기 | 의미 |
|---|---|
| **[D]** | Palantir 공식 문서에서 확인한 실제 동작 |
| **[B]** | Blueprint 소스 코드(`variables.less`)에서 확인한 실제 값 |
| **[P]** | 확인된 사실이 아닌, 일반적인 관제 UI 패턴에 근거한 제안 |

**[P] 항목은 팔란티어가 그렇게 한다는 근거가 없다.** 이 프로젝트의 요구사항에 맞춰 자유롭게 바꿔도 되는 부분이다.

확인에 사용한 1차 출처는 15장에 정리했다.

---

## 1. 범위

지도를 작업 표면으로 삼아 다중 레이어를 중첩하고, 객체를 선택하고, 시간축을 이동하며, 액션을 지시하는 콘솔 UI의 설계 기준.

제외: 백엔드 파이프라인, 인증/권한 서버, 타일 서빙 인프라.

---

## 2. 설계 철학

**[D] 지도 위 점은 좌표가 아니라 온톨로지 객체다.**
Foundry Map에 올라가는 데이터는 두 종류뿐이다. 지리 정보를 가진 **온톨로지 객체(Ontology objects)**, 그리고 미리 구성된 **오버레이(Map overlays)**. 좌표 배열이 아니라 타입·속성·관계를 가진 객체를 올린다는 것이 이 계열의 출발점이다. 이게 없으면 아래 모든 상호작용(Search Around, 액션, 히스토그램 필터)이 성립하지 않는다.

**[D] 공간과 시간은 분리되지 않는다.**
타임라인이 닫혀 있어도 타임라인의 시간 범위와 선택 시각은 지도 위 모든 시간 기반 데이터에 계속 영향을 준다. 시간은 켜고 끄는 기능이 아니라 지도의 상시 좌표축이다.

**[D] 관계 탐색이 일급 기능이다.**
지도 위에서 객체를 선택한 뒤 **Search Around**로 온톨로지 관계를 타고 연결된 객체를 지도에 추가할 수 있다. 추가된 객체가 점으로 표시되면 지도가 둘 사이에 시각적 링크를 그린다. 이건 부가 기능이 아니라 상단 툴바에 상시 노출된 7개 도구 중 하나다.

**[P] 정보 밀도가 여백보다 우선한다.**
Blueprint의 기본 수치(행 30px, 폰트 14px, 그리드 10px, 반경 2px)가 이미 고밀도 데스크톱 앱을 전제로 설계돼 있다. 그 값을 그대로 쓰면 밀도는 따라온다.

**[P] 색은 인코딩이지 장식이 아니다.**
한 화면에서 색이 상태와 소속을 동시에 의미하면 판독이 무너진다. 축 하나에만 매핑한다.

## 3. 화면 구조 [D]

Foundry Map의 실제 인터페이스 구성. 이게 검증된 골격이다.

```
┌──────────────────────────────────────────────────────────────────┐
│ Select │ Search Around │ Draw │ Capture │ Measure │ Annotate │ ✕  │  툴바
├────────────┬─────────────────────────────────────┬───────────────┤
│  Layers    │                                     │  Selection    │
│  Find      │                                     │  Time         │
│  Histogram │              지  도                  │  Selection    │
│  Info      │                                     │               │
│            │                                     │  ┌─────────┐  │
│            │                                     │  │ Series  │  │
│            │  [Timeline] ← 좌하단 버튼            │  └─────────┘  │
├────────────┴─────────────────────────────────────┴───────────────┤
│  ◀ ═══════●══════════════════════════▶  [⏵] [1x]   (접기 가능)    │  타임라인
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 좌측 패널 4종 [D]

| 패널 | 역할 |
|---|---|
| **Layers** | 객체·오버레이 레이어 추가·관리·스타일링, 베이스 레이어 설정 |
| **Find** | 객체와 장소 검색, 특정 좌표로 이동 |
| **Histogram** | 속성값·시계열값 기준으로 객체 분석 및 필터링 |
| **Info** | 지도 전체 요약 |

주목할 점: **필터링이 히스토그램 패널에 들어 있다.** 필터 폼이 아니라 분포 차트가 필터 UI다. 값 분포를 보면서 구간을 집는 방식이라, "어떤 값이 있는지 모르는 상태"에서도 필터를 걸 수 있다.

### 3.2 우측 패널 [D]

| 패널 | 역할 |
|---|---|
| **Selection** | 선택 항목의 상세 확인 및 **액션 실행** |
| **Time Selection** | 지도와 시계열 뷰에 적용할 시간 범위·현재 시각 설정 |

우하단에 **Series** 패널이 별도로 있어 시계열·이벤트 데이터의 시간 분석을 담당한다.

조회와 지시가 같은 패널(Selection)에 있다는 점이 중요하다. 선택 → 확인 → 지시가 한 자리에서 끝난다.

### 3.3 상단 툴바 7종 [D]

| 도구 | 기능 |
|---|---|
| **Select** | 전체 선택, 선택 반전, 그린 도형과 교차하는 항목 선택 |
| **Search Around** | 객체 관계 탐색 |
| **Draw** | 폴리곤·원·사각형·선·점 그리기 및 조작 |
| **Capture** | 현재 지도 상태 스크린샷 |
| **Measure** | 실제 거리 측정 |
| **Annotate** | 텍스트·폴리곤 주석 추가 |
| **Delete** | 지도에서 항목 제거 |

**Capture가 일급 도구라는 점이 시사적이다.** 관제 업무의 산출물은 보고이고, 보고에는 화면 캡처가 들어간다. 이걸 OS 캡처 도구에 맡기지 않고 앱 안에 넣었다.

### 3.4 패널 크기 [P]

| 영역 | 권장 |
|---|---|
| 툴바 | 높이 40px 고정 |
| 좌측 패널 | 280px, 220–420px 리사이즈, 아이콘 레일로 접기 |
| 지도 | 잔여 전체, 최소 폭 480px |
| 우측 패널 | 320px, 280–560px 리사이즈 |
| 타임라인 | 56px, 접기 가능 |

패널 폭은 사용자가 조절하고 그 값을 저장한다. 4K·듀얼 모니터가 기본 환경이고 1280px는 하한이다.

## 4. 레이어 [D]

### 4.1 레이어 조작

- **표시/숨김**: 가시성 토글
- **이름 변경**: 현재 이름을 클릭해 인라인 편집
- **순서 변경**: 레이어 아이콘을 드래그. **목록에서 위에 있는 레이어가 위에 렌더된다.**
- **객체 분리**: 선택한 객체들을 새 레이어 또는 기존 레이어로 이동. **단, 같은 객체 타입끼리만 가능.** 분리한 뒤 각 레이어를 다르게 스타일링한다.

**여기서 제가 이전 버전에 잘못 쓴 것**: z-order를 고정 계층으로 설계하라고 썼는데, 실제로는 사용자가 드래그로 자유롭게 바꾼다. 렌더 순서는 시스템이 정하는 규칙이 아니라 사용자가 조절하는 상태다. 순서를 상태에 저장하고 드래그 핸들을 제공해야 한다.

객체를 레이어로 쪼개 각각 다르게 스타일링하는 패턴도 놓쳤던 부분이다. "레이어 = 데이터 소스"가 아니라 "레이어 = 스타일 단위"에 가깝다.

### 4.2 레이어 시각화 유형

공식 문서가 정의하는 표현 방식은 다음 6종이다.

| 유형 | 용도 |
|---|---|
| **Points** (아이콘·원) | 지점 객체 |
| **Lines and polygons** | 경로, 영역 |
| **Choropleths** | 경계 단위 단계구분도 |
| **Clusters** | 밀집 지점 집약 |
| **Timeline events** | 타임라인에 나타나는 이벤트 지오메트리 |
| **Tracks** (이동체) | 움직이는 객체의 궤적 |

Choropleth는 Mapbox와 협업해 행정구역·우편번호 같은 경계 집합(Boundaries)을 관리형으로 제공하며, 데이터셋·온톨로지 값으로 폴리곤 색을 구동한다.

### 4.3 지도에 데이터 추가하는 경로 [D]

1. **객체 검색 다이얼로그** — 자연어 질문 입력, 좌측 필터 패널, 객체 타입 선택 후 속성 필터 추가. `Cmd/Ctrl` 토글 선택, `Shift` 범위 선택.
2. **공간 검색** — `Add to map` → `Search for objects that intersect a shape...` → 도형을 그리면 그 도형과 교차하는 객체만 결과에 표시.
3. **오버레이** — Map Layer Editor에서 만든 재사용 가능한 레이어. 이름·태그·경로·작성자로 검색.
4. **Search Around** — 지도 위 객체에서 관계를 타고 연결 객체 추가.

**객체 추가 한도는 기본 1,000개**다. 한도에 걸리면 `Add all`이 비활성화되고 필터로 줄여야 다시 활성화된다.

### 4.4 심볼 인코딩 [P]

한 심볼이 전달 가능한 축은 최대 4개다.

| 채널 | 인코딩 |
|---|---|
| 모양(아이콘) | 객체 타입 |
| 색 | 상태 **또는** 소속 (택 1) |
| 크기 | 규모·중요도 |
| 테두리 | 선택·포커스 |

점멸은 최고 심각도에만 허용한다. 클러스터 배지에는 개수와 함께 **내부 최고 심각도 색**을 표시한다. 클러스터가 초록인데 안에 경보가 숨어 있으면 치명적이다.

## 5. 시간 모델 [D]

**이 장이 이 문서에서 가장 중요하다.** 시간 관련 개념이 셋으로 분리돼 있고, 이걸 하나로 뭉뚱그리면 구현이 반드시 꼬인다.

### 5.1 세 가지 시간 개념

| 개념 | 정체 | UI |
|---|---|---|
| **Selected time** (선택 시각) | 지도가 보여주는 "지금" 한 시점 | 타임라인 위 커서 |
| **Time range** (시간 범위) | 타임라인이 표시하는 창 | 타임라인 좌우 끝 |
| **Filtered time window** (필터 구간) | 강조할 구간 | 타임라인 위 브러시 영역 |

Selected time은 **점**, time range는 **보이는 창**, filtered window는 **필터**다. 셋 다 독립적으로 움직인다.

### 5.2 선택 시각 조작

- 타임라인을 더블클릭 또는 우클릭
- 커서를 드래그
- 타임라인 헤더 중앙의 날짜/시각을 클릭해 날짜·시간 피커 입력

날짜·시간 선택기에서는 **객체 레이어의 현재 시간 범위 안에 있는 시각만 고를 수 있다.**

### 5.3 실시간 모드

**View latest**를 선택하면 선택 시각이 현재 시각으로 설정된다. **Latest Data** 뷰에서는 선택 시각이 현재 시각을 자동 추종한다. 스트리밍 파이프라인과 조합하면 실시간 갱신 지도가 된다.

폴링 간격은 Control Panel에서 전역 설정, 설정 패널에서 지도별로 **폴링 간격·타임존·시간 형식**을 개별 설정한다. 타임존이 지도 단위 설정이라는 점은 그대로 가져갈 만하다.

### 5.4 시간 범위 조작

- 스크롤 휠 → 타임라인 확대/축소
- `Cmd/Ctrl` + 스크롤 → 시간 범위 이동(팬)
- 트랙패드 수직 스와이프/핀치 → 확대/축소
- 헤더 우측 **Time range**로 구체적 범위 직접 입력
- **Zoom to fit**(양방향 화살표) → 데이터에 맞춰 자동 조정

### 5.5 시간 필터 — 숨기지 않고 흐린다

`Shift` + 타임라인 드래그, 또는 **Time filter** 버튼으로 필터 구간을 만든다. Time filter는 지도 캔버스 상단에도 노출된다.

**핵심 동작: 필터에 맞는 객체는 완전 불투명, 맞지 않는 객체는 흐려진다.** 사라지는 게 아니다.

이건 의도된 설계다. 관제에서 객체가 화면에서 없어지면 "필터에 걸린 것"과 "존재하지 않는 것"이 구분되지 않는다. 흐리게 남기면 맥락이 유지된다. 필터 = 숨김이라는 기본 가정을 버려야 한다.

### 5.6 재생

`⏵` 버튼으로 커서 자동 이동. 속도 프리셋은 **1x, 2x, 5x, 10x, 100x** 등. 커서는 타임라인의 시간 창 안에서, 시간 필터가 있으면 **그 필터 구간 안에서 자동 반복(loop)** 한다.

### 5.7 접힘 상태의 동작

타임라인이 접혀 있으면 타임라인에 추가된 데이터는 보이지 않지만, **시간 범위·필터 구간·선택 시각은 여전히 변경 가능하고 지도에 계속 적용된다.**

**Expand**(위쪽 이중 꺾쇠)를 누르면 객체 타입별로 각각의 타임라인 행이 생긴다. 타임라인의 모든 데이터는 객체 타입 단위로 묶인다.

### 5.8 타임라인 표현

- 시점 속성 → **선(line)**
- 기간 속성 → **막대(bar)**
- **Track breadcrumbs**: 궤적의 위치 기록 시점이 타임라인에 찍힌다. 선택 시각을 옮기면 궤적 경로가 애니메이션된다. 단, 렌더 여부가 **시간 범위와 지도 뷰포트 양쪽**에 의존한다.

## 6. 데이터 로딩 — 설계 최대 제약 [D]

객체 수에 따라 로딩 방식이 자동으로 갈리고, **방식에 따라 사용할 수 있는 기능이 달라진다.**

| | Object-based | Tile-based |
|---|---|---|
| 적용 | 소규모 객체 집합 | **1,000개 초과 시 자동 전환** |
| 타임라인 이벤트 | 가능 | **불가** |
| 시간 기반 스타일링 | 가능 | **불가** |
| 시간 필터 구간 | 가능 | **불가** |

**이 트레이드오프가 설계 전체를 지배한다.** "대량 객체 + 완전한 시간 분석"은 동시에 성립하지 않는다. 팔란티어조차 이걸 해결하지 못하고 사용자에게 선택시켰다.

따라서 요구사항을 정할 때 반드시 먼저 답해야 한다:

- 동시에 지도에 올릴 객체 수의 현실적 상한은?
- 시간 재생·시간 필터가 정말 필요한 레이어는 어느 것인가?

전 레이어에 시간 기능을 넣겠다고 하면 객체 수 상한을 낮춰야 한다. 반대로 수만 개를 뿌리겠다면 그 레이어에서는 시간 기능을 포기해야 한다. **레이어 단위로 이 결정을 다르게 가져가는 게 현실적인 절충이다.**

## 7. 디자인 토큰 [B]

Blueprint는 팔란티어가 만들어 오픈소스로 공개한 디자인 시스템이다. 아래는 `@blueprintjs/core`의 `variables.less` 실제 값이다.

### 7.1 그레이스케일 — UI 프레임 전용

```css
--black:       #111418;
--dark-gray1:  #1c2127;
--dark-gray2:  #252a31;   /* 다크 앱 배경 */
--dark-gray3:  #2f343c;
--dark-gray4:  #383e47;
--dark-gray5:  #404854;
--gray1:       #5f6b7c;
--gray2:       #738091;
--gray3:       #8f99a8;
--gray4:       #abb3bf;   /* 다크 보조 텍스트 */
--gray5:       #c5cbd3;
--light-gray1: #d3d8de;
--light-gray5: #f6f7f9;   /* 다크 본문 텍스트 */

```

공식 문서 원문: 그레이스케일은 컨테이너·헤더·섹션·박스 등 **주요 UI 프레임에 사용**하고, 버튼·아이콘·툴팁처럼 주의를 끌어야 하는 요소에는 아래 코어 컬러를 쓴다.

### 7.2 코어 컬러 — 인텐트

```css
--blue1:#184a90; --blue2:#215db0; --blue3:#2d72d2; --blue4:#4c90f0; --blue5:#8abbff;

--intent-warning: #c87619;   /* Orange — 경고, 중간 상태 */
--intent-danger:  #cd4246;   /* Red    — 오류, 파괴적 동작 */
```

코어 컬러는 WCAG 2.0을 준수하도록 설계됐다. 다크 배경에서는 3번이 아니라 4~5번 계열을 써야 대비가 확보된다.

## 8. Gaia 추가 사항 [D]

Gotham의 지리공간 앱 Gaia는 Foundry Map과 별개 제품이며, Gotham 라이선스가 있어야 접근 가능하다. 참고할 만한 특성:

- **외부 포맷 수용**: SHP, KMZ, KML, LYR 등 커스텀 타일셋·레이어 포맷·오버레이 지원
- **외부 플랫폼 연동**: ATAK, WINTAK, Mapbox 등
- **지오태깅**: 엔티티·이벤트·미디어(이미지 포함)에 지리 메타데이터를 사용자가 부여. 내재적이든 사용자 추가든 지리 메타데이터가 있으면 공간 분석 대상이 된다.
- **지오서치 유형**: 반경(radius), 경로(route), 폴리곤, 시간(temporal)
- **드래그 앤 드롭**: Foundry에서 개별 객체나 저장된 탐색 결과(최대 5,000개)를 Gaia 지도로 끌어다 놓기
- **Enterprise Map Layers (EML)**: 관리자가 정의하는 조직 단위 공용 레이어

**"사용자가 지오태그를 붙일 수 있다"는 점이 중요하다.** 지리 정보가 없던 객체도 사용자가 위치를 부여하면 지도에 올라온다. 데이터 모델을 짤 때 좌표를 필수 필드로 강제하지 말 것.

Gaia 지도는 API로 구조를 읽을 수 있고, 응답의 `rootLayerIds`와 각 레이어의 `subLayerIds`로 **레이어 계층을 재구성**한다. 레이어가 중첩 구조라는 뜻이다.

## 9. 액션 (지시) [P]

Foundry Map은 Selection 패널에서 액션을 실행하고, 온톨로지 액션을 지도에 연동한다 [D]. 세부 UX는 확인하지 못했으므로 아래는 제안이다.

- 액션은 **대상 → 액션 → 확인 → 결과** 4단계를 거친다. 원클릭 실행 없음.
- 확인 단계에서 영향 범위를 숫자로 명시한다. "3개 대상에 적용됩니다."
- 결과는 토스트가 아니라 **액션 로그**에 남긴다. 누가·언제·무엇을·왜. 토스트는 사라지지만 관제 기록은 남아야 한다. (Foundry에는 실제로 Action log와 Action revert 기능이 있다 [D])
- 되돌릴 수 있는 액션과 없는 액션을 시각적으로 구분한다. 비가역 액션은 `danger` 인텐트 + 명시적 텍스트 확인.

## 11. 상태 모델 [P]

```ts
interface ConsoleState {
  view: { center: [number, number]; zoom: number; bearing: number; pitch: number };

  layers: Array<{                     // 배열 — 순서가 곧 렌더 순서 [D]
    id: string;
    name: string;                     // 인라인 편집 가능 [D]
    visible: boolean;
    objectType: string;               // 레이어당 단일 타입 [D]
    style: LayerStyle;
    filters: Filter[];
    loading: 'object' | 'tile';       // 1000개 초과 시 tile [D]
    subLayerIds?: string[];           // 중첩 가능 [D]
  }>;

  time: {
    selectedTime: number;             // 커서 = 한 시점 [D]
    range: [number, number];          // 보이는 창 [D]
    filterWindow: [number, number] | null;  // 필터 구간 [D]
    latestMode: boolean;              // View latest 추종 [D]
    playback: { playing: boolean; speed: 1|2|5|10|100 };  [D]
    timezone: string;                 // 지도 단위 설정 [D]
    pollingInterval: number;          // 지도 단위 설정 [D]
  };

  selection: { objectIds: string[]; focusedId: string | null };
  shapes: Shape[];                    // 그린 도형 = 저장 가능한 객체
  annotations: Annotation[];
  panels: { left: PanelId | null; right: PanelId | null; timeline: boolean };
}
```

- `time`의 세 필드를 하나로 합치지 말 것. 실제 제품이 셋으로 분리해 둔 데는 이유가 있다.
- 파생값(필터 통과 객체, 뷰포트 내 객체, 클러스터)은 저장하지 않고 계산한다.
- 상태 전체를 URL에 직렬화한다. 관제 업무는 "이 화면 좀 봐줘"라고 링크를 던지는 일이 절반이다. (Foundry에도 Object Explorer/Object View URL 생성 기능이 있다 [D])

## 12. 성능 [P]

| 항목 | 목표 |
|---|---|
| 초기 지도 표시 | < 2s |
| 레이어 토글 반영 | < 100ms |
| 시간 커서 스크럽 | 30fps 이상 |
| 마커 10,000개 | 60fps |
| 객체 선택 → 패널 | < 150ms |

- 마커를 DOM으로 그리지 않는다. WebGL 레이어(deck.gl `ScatterplotLayer`/`IconLayer`)로 간다.
- 아이콘은 스프라이트 아틀라스 한 장으로 묶는다.
- 뷰포트 밖 객체는 계산에서 제외한다. 실제로 track breadcrumbs 렌더가 뷰포트에 의존한다 [D].
- 대량 데이터는 타일 단위로 나눈다(`MVTLayer`). 단, 6장의 기능 제약을 감수해야 한다.
- 실시간 이벤트는 버퍼링 후 프레임 단위 일괄 반영(100–250ms). 연결 상태(연결됨/재연결 중/끊김 + 마지막 수신 시각)를 항상 표시한다.

## 13. 기술 스택 [P]

| 영역 | 선택 | 비고 |
|---|---|---|
| 베이스맵 | MapLibre GL JS | 오픈소스 벡터 타일 |

Blueprint 컴포넌트를 안 쓰더라도 **7장의 토큰만은 채택**하는 편이 낫다. 자체 팔레트를 새로 만들면 다크 테마 대비 검증에만 몇 주가 든다.

## 14. 로드맵 [P]

| 단계 | 내용 | 기간 |
|---|---|---|
| 1 | 골격: 지도 full bleed + 좌/우 패널 + 토큰 적용 | 1–2주 |
| 2 | 레이어: 트리, 토글, **드래그 순서 변경**, deck.gl 렌더, 스타일링 | 2–3주 |
| 3 | 객체 모델: 선택, Selection 패널, **Search Around 관계 탐색** | 2–3주 |
| 4 | 시간: **세 개념 분리 구현**, Latest 모드, 재생, 흐림 필터 | 2–3주 |
| 5 | 질의: Draw, 공간 검색, Histogram 필터, 필터 칩 | 2주 |
| 6 | 액션·경보: 4단계 플로우, 액션 로그, 경보 큐 | 2–3주 |
| 7 | 실시간·성능: 폴링/스트리밍, 버퍼링, tile/object 전환 | 2주 |

레이아웃(1단계)은 금방 끝난다. 실제 난이도는 **3단계 관계 탐색**과 **4단계 시간 모델**, **7단계 로딩 전환**에 몰려 있다. 일정을 여기에 배분한다.
