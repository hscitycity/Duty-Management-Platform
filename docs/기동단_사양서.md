# 기동단_사양서.md

교통·도로민원 신속처리 기동단 작업판(`#road`) 사양

> 운영 개시 **2026. 9. 7.** · 대표전화 **1833-4088**
> 현재 구현은 처리기한·유형·절차가 실제 업무와 다르다. 이 문서 기준으로 교체한다.

---

## 0. 명칭

**정식 명칭은 「교통·도로민원 신속처리 기동단」이다.**

| 위치 | 표기 |
|---|---|
| 화면 제목·문서·제안서 | 교통·도로민원 신속처리 기동단 |
| 화면 탭·목록 등 좁은 자리 | **교통·도로 기동단** |
| 금지 | `기동단`, `신속기동단`, `도로기동단` |

`교통·도로`까지가 최소 단위다. 이보다 줄이지 않는다. 기존 화면·데이터·시나리오의 표기를 전부 교체한다.

## 1. 실제 업무 흐름

```
전화 접수(1833-4088) 또는 시민창구·당직 이관
        ↓
기동단 접수 등록
        ↓
현장 확인 및 민원 분류           ← 기동단이 직접 한다
        ↓
처리방안 안내  【접수 후 1시간 이내】  ← 시민과의 첫 약속
        ↓
관계 부서·기관 협력 처리
   즉시 24시간 / 단기 48시간 / 중장기 협의
        ↓
진행상황·결과 안내
```

**기동단은 처리 주체가 아니라 접수·분류·조율 주체다.** 실제 조치는 소관 부서·기관이 한다. 현재 구현은 기동단이 직접 처리하는 전제로 되어 있어 협력 단계가 빠져 있다.

## 1-1. 전담 인력과 접수

**기동단에는 전담 인력이 배치되어 직접 민원을 접수한다.** 당직자가 대신 받는 구조가 아니다.

| 항목 | 내용 |
|---|---|
| 접수 경로 | 대표전화 **1833-4088**(주 경로) · 24시간 민원접수창구 · 당직 이관 · 타 기관 이관 |
| 접수 주체 | 기동단 전담 인력 |
| 소속 | 소속 선택에서 `부서 → 교통·도로민원 신속처리 기동단` |
| 기본 화면 | 기동단 소속으로 접속하면 `#road`가 첫 화면 |

### 배정 규칙

- 민원 접수 시 **담당 주체를 당직 처리 / 교통·도로 기동단 중에 정한다.** AI가 유형(3장 5분류)을 근거로 먼저 제안하고 접수자가 확정한다.
- 기동단으로 배정되면 접수·현장확인·안내·협력·처리·결과안내 **전 과정을 기동단이 관리**한다. 상황판에서는 건수와 목록만 보인다.
- **긴급과 기동단은 축이 다르다.** 인명·안전 위험이면 긴급으로 표시되고 당직이 우선 조치하되, 기동단이 병행 관리한다. 한 건이 상황판 긴급 목록과 기동단 목록에 모두 나타날 수 있다.
- 당직 접수 건 중 도로교통 유형이면 **기동단 이관** 처리하고, 이관 시각과 사유를 기록한다.

## 2. 처리구분 【현재 값이 전부 틀림】

| 구분 | 기한 | 대상 |
|---|---|---|
| **즉시** | **24시간** | 신호기 고장, 표지판·반사경 파손, BIS 오류 등 |
| **단기** | **48시간** | 시설물 파손, 정류장 시설 개선 등 |
| **중장기** | 관계기관 협의 (기한 미정) | 도로 혼잡, 신호체계 개선, 버스노선 개선 등 |

현재 구현은 즉시 4시간 · 단기 7일 · 중장기 6개월로 되어 있다. **전부 교체한다.**

중장기는 종료 기한이 없으므로 **경과일과 현재 단계**로 관리한다. 남은 시간을 표시하지 않는다.

## 3. 민원 유형 5분류

접수·분류·통계의 기준 축이다.

| # | 유형 | 세부 | 주 소관 |
|---|---|---|---|
| 1 | **도로 파손·침하** | 포트홀, 도로 침하, 보도 파손 | 도로과 / 구청 안전건설과 |
| 2 | **교통시설 고장·파손** | 신호기 고장, 표지판·반사경 파손, BIS 오류 | 교통정책과 · 대중교통과(BIS) |
| 3 | **불법주정차·통행 불편** | 불법주정차, 방치 PM, 무단방치 차량 | 주차물류과 / 구청 |
| 4 | **버스 이용 불편** | 무정차, 난폭운전, 배차간격, 정류장 시설 | **대중교통과 + 운수업체** |
| 5 | **교통체계 개선** | 도로 혼잡, 신호체계 개선, 버스노선 개선 | 교통정책과 (+경찰 협의) |

**4번 버스 민원은 처리 경로가 다르다.** 시설 조치가 아니라 **운수업체 확인·회신**을 거친다. 업체 통보 시각과 회신 시각을 별도로 기록한다. 현재 시스템에는 이 유형과 경로가 없다.

**5번은 대부분 중장기**이며 경찰 협의(교통안전시설 심의)가 필요한 건이 많다.

### 3-0. 안내문의 중심은 처리구분이다

기동단의 핵심은 「언제까지 처리되는가」다. 안내문 맨 앞에 **즉시 · 단기 · 중장기**를
세 장의 카드로 크게 두고, **각 구분에 무엇이 들어가는지**를 함께 적는다.

| 구분 | 기한 | 무엇이 |
|---|---|---|
| **즉시** | 24시간 내 조치 | 신호기 고장 · 표지판·반사경 파손 · BIS 오류 · 포트홀 · 도로 침하 |
| **단기** | 48시간 내 처리 | 가로등·보안등 고장 · 시설물 파손 · 정류장 시설 개선 · 빗물받이 막힘 |
| **중장기** | 관계기관 협의 | 도로 혼잡 · 신호체계 개선 · 버스노선 개선 · 시설 신설·이설 |

처리구분은 **현장 확인 뒤 확정**한다. 어느 구분이든 접수 후 60분 이내에 방향을 먼저 알린다.

### 3-0-1. 안내 대기 화면은 한 가지만 한다

안내 대기 열의 민원을 누르면 **처리방안 안내 화면 하나만** 연다.
현장 확인·사진·처리결과는 그 다음 단계의 일이므로 이 화면에 두지 않는다.

- 마감 시각을 가장 크게 · 남은 시간과 상태색(정상·주의·임박·초과)
- 민원 요약 4줄(유형·위치·내용·소관)
- **안내 문안은 AI 가 열자마자 초안을 만든다.** 실패해도 규칙 초안으로 채운다
- 안내 방법 + [안내 완료 기록] — 기한 내/초과를 이력에 남긴다
- 전체 상세가 필요하면 [전체 상세 보기]로 간다

### 3-1. 안내문은 이 표를 참조한다 【중요】

> **안내문이 뜨는 자리**: 기동단 화면(`#road`) 머리줄의 **[기동단이란]** 버튼.
> 그 화면 안에서 아래로 펼쳐진다. 모달로도, 다른 화면의 우측 패널로도 띄우지 않는다.
> **[전화 접수]** 는 팝업을 띄우지 않고 `민원현황-접수` 화면의 기동단 접수 서식으로 이동한다
> (지도에서 위치를 찍고 통화 내용을 이어 적는 화면).


상황판 우측 패널 ⑤ **기동단 안내**(`상황판_사양서.md` 6.5)의 5개 유형은
**이 3장 유형표와 같은 데이터다.** 처리구분 기한 문구는 **2장 기한표**를 참조한다.

| 쓰이는 곳 | 참조 상수 | 근거 장 |
|---|---|---|
| 안내문 5개 유형 | `ROAD_CATS` | 3장 |
| 접수 화면 유형 버튼 | `ROAD_CATS` | 3장 |
| 분류 로직(`roadCat`) | `ROAD_CATS` | 3장 |
| 안내문 처리구분 기한 | `TRIAGE_META` · `TRIAGE_MS` | 2장 |
| 「접수 후 1시간 이내」 | `GUIDE_MIN` | 5.1 |

**유형이나 기한을 바꿀 때는 상수 한 곳만 고친다.**
안내문에 문구를 따로 적어 두면 유형이 추가될 때 안내문·접수 버튼·분류 로직 세 군데가 어긋난다.

## 4. 화면 구성

### 4.1 상단 — 세 개의 시계

```
┌──────────────────────────────────────────────────────┐
│ 안내 대기 3건 ⏱ 최소 12분 남음   │ 즉시 5 │ 단기 8 │ 중장기 4 │
└──────────────────────────────────────────────────────┘
```

**「안내 대기」가 가장 왼쪽·가장 크게 온다.** 접수 후 1시간 이내 처리방안 안내가 기동단의 첫 약속이고, 24·48시간보다 먼저 오는 마감이기 때문이다.

- 남은 시간 20분 이하 주황, 10분 이하 적색, 초과 시 적색 배경 + 건수 강조
- 나머지 지표: 기한 임박 · 기한 초과 · 오늘 완료

### 4.2 본문 — 4열

| 열 | 내용 | 관리 기준 |
|---|---|---|
| **안내 대기** | 접수됐으나 처리방안 미안내 | **남은 시간(1시간 카운트다운)** |
| **즉시** | 24시간 | 남은 시간 |
| **단기** | 48시간 | 남은 시간 |
| **중장기** | 협의 진행 | 경과일 + 단계(5단계 중 몇) |

- 「안내 대기」 열이 비어 있는 것이 정상 상태다. 쌓이면 약속을 어기고 있다는 뜻이다.
- 분류 전 건은 안내 대기 열에만 있고, 분류하면 해당 열로 이동한다.

### 4.3 민원 카드

```
[유형색 바] 09:45  포트홀 · 도로 파손        [📷] [24시간]
            매송면 원평리 312 · #13670
            ⏱ 안내까지 12분 남음 · 접수 전화(1833-4088)
```

- 1줄: 시각 · 세부유형 · 대분류 · 사진 · 기한 배지
- 2줄: 위치 · 접수번호
- 3줄: **마감 시계** + 접수 경로
- 유형색은 5분류 기준. 기한은 배지로 구분(색을 두 축에 쓰지 않는다)

### 4.4 상세 (선택 시)

| 구획 | 내용 |
|---|---|
| 접수 | 시각 · 경로(전화/창구/이관) · 신고 내용 · 사진 |
| **처리유형 분류(즉시/단기/중장기)** | 접수 때 AI 가 1차로 나눈 값 · 담당자는 **고칠 때만** 쓴다 |
| **처리방안 안내** | 안내 시각 · 안내 내용 · 안내 방법(전화/문자) · **1시간 준수 여부** |
| **유관기관 의견등록** | 유관 기관 · 의견요청서 내려받은 시각 · 회신받은 의견 |
| **처리 결과안내** | 조치 경과 · 현장사진 · 민원인 회신 |

버스 민원은 「유관기관 의견등록」에 **운수업체**가 필수로 붙는다.

**기동단은 현장에 나가는 주체가 아니다.** 상세에 「현장 확인」 구획을 두지 않는다.
현장사진은 담당 부서가 상황판(C-4a 초동조치 · 현장사진 등록)에서 올리고, 기동단은 그것을 **보기만** 한다.

## 5. 신규 기능

### 5.1 안내 마감 알림 【최우선】

- 접수 시각부터 60분 카운트다운 시작
- 잔여 20분·10분·0분에 화면 상단 알림
- 초과 건은 「안내 대기」 열 최상단에 적색 고정
- 통계에 **1시간 준수율**을 지표로 둔다. 이것이 기동단의 핵심 성과 지표다

### 5.2 전화 접수 창구

- 대표전화 **1833-4088** 접수 건을 위한 빠른 등록 화면
- 통화 중 입력을 전제로 필드를 최소화: 유형 5개 버튼 → 위치 → 내용
- 기존 AI 접수 서기(자유 기록 → 구조화)를 그대로 재사용한다
- 접수 완료 시 **안내 마감 시각을 즉시 표시**해 상담원이 약속을 인지하게 한다

### 5.3 처리유형 분류 수정

- **분류는 접수 때 AI 가 이미 1차로 끝냈다.** 담당자는 그것이 틀렸을 때만 고친다.
  「현장 확인」이라 부르지 않는다 — 기동단이 현장에 나가는 단계가 아니다.
- 화면에는 현재 분류와 그 **기준**(즉시/단기/중장기 판단 근거)을 먼저 보여 준다.
- **고쳐도 창이 닫히지 않는다.** 유형과 처리구분을 잇달아 손볼 수 있어야 한다.
  닫히는 것은 닫기 버튼을 누르거나 바깥을 눌렀을 때뿐이다.

### 5.4 유관기관 의견등록 (B-7 · B-8)

- **이 시스템으로 타 기관에 통보할 수 없다.** 통보한 척하는 기록을 남기지 않는다.
- 대신 **의견요청서를 파일로 내려받아**(B-7) 공문·팩스로 보낸다.
  요청서에는 민원 개요·민원 내용·지금까지 조치한 내용·요청 사항이 담긴다.
  (상황판의 이관 인계서 C-4c4 와 같은 방식이다.)
- 회신받은 의견은 같은 자리에서 적는다(B-8). 적어도 창은 닫히지 않는다.
- 유관 기관: 경찰서, 운수업체, 한국도로공사, 한국전력, 한국가스공사, 통신사, 시설관리공단

### 5.5 처리 결과안내 (B-9)

- 이 자리에서 하는 일은 하나다 — **지금까지의 조치와 사진을 보고 신고인에게 알린다.**
- 조치 경과와 현장 담당자가 올린 사진이 **펼친 채로 바로** 보인다.
- **상세 머리(B-9b)는 위에 고정한다.** 민원 제목 · `조치사항 등록`(우측 상단) · 남은 시간까지가 한 덩어리다.
  아래로 내려갈수록 어느 민원을 보고 있고 시간이 얼마 남았는지가 더 필요하다.
- **사진도 조치도 이 자리에서 적지 않는다.** `조치사항 등록`(B-9a)을 누르면
  상황판의 해당 민원으로 넘어가고, 거기서 초동조치·현장사진을 적는다.
  두 곳에서 적으면 어느 쪽이 참인지 알 수 없다.
- **민원인 회신(B-10)은 상세 맨 아래 닫기 옆**에 둔다. 상세를 다 읽고 마지막에 하는 일이다.
- 구획 머리의 상태 글씨(`AI 1차 분류` `기한 초과` `의견 대기` `회신 전`)는 **제목 바로 옆**에 붙인다.
  오른쪽 끝으로 밀면 어느 제목의 상태인지 짝이 지어지지 않는다. 오른쪽에는 펼침 화살표만 둔다.

## 7. 다른 화면과의 관계

| 화면 | 분류 축 |
|---|---|
| 당직 상황판 `#duty` | 긴급 / 일반 / 처리중 |
| **교통·도로 기동단 `#road`** | **안내대기 / 즉시 / 단기 / 중장기** |

두 축을 섞지 않는다. 도로교통 민원이 상황판에 들어오면 **기동단으로 이관**하고, 상황판 목록에서는 「기동단 이관」 표시만 남긴다.

시민 처리현황(`#track`)에서 기동단 민원은:
- 안내 전 — `1시간 이내에 처리 방향을 알려드립니다`
- 안내 후 — 안내 내용 + 처리구분별 예정 시각
- 중장기 — 5단계 진행 표시

## 8. 검증

- [ ] 명칭이 `교통·도로민원 신속처리 기동단` / 좁은 곳은 `교통·도로 기동단`
- [ ] 처리기한이 24시간 · 48시간 · 협의로 표시
- [ ] 안내 대기 열이 최상단·최좌측에 있고 카운트다운이 동작
- [ ] 5개 유형으로 분류·필터 가능
- [ ] 버스 민원에 운수업체 협력 항목이 뜸
- [ ] 전화 접수 화면에서 안내 마감 시각이 즉시 표시
- [ ] 1시간 준수율이 지표로 집계
- [ ] 중장기 건에 남은 시간 대신 경과일·단계가 표시
- [ ] 상황판과 분류 축이 섞이지 않음
